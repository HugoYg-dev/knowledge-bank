## 二、 规划文档核心内容设计

规划文档将包含以下 5 大核心章节：

### 1. 背景与核心价值
- 解决历史积累中纯英文命名（67篇）、中英倒置命名（28篇）导致的中文检索漏检、英文缩写心智不统一与图谱可读性差的痛点。
- 确立统一心智：文件名自解释 + 中英双向毫秒级检索命中。
- 激活 Obsidian 未链接提及（Unlinked Mentions）复利效应。

### 2. 概念命名三分层权威规范
全库 `wiki/concepts/` 下所有文件一律以 `概念_` 作为物理前缀，采用**下划线 `_` 作为天然语义分界符**：
- **规则 1：英文缩写 + 中文核心名（业内通用首字母缩写）**
  - **格式**：`概念_{英文缩写}_{中文核心名}.md`
  - **范例**：`概念_RLVR_可验证奖励强化学习.md`、`概念_PCA_主成分分析.md`、`概念_LoRA_低秩适应微调.md`、`概念_DPO_直接偏好优化.md`、`概念_GQA_分组查询注意力.md`
- **规则 2：英文专名 + 中文核心名（专有算法/复合名词）**
  - **格式**：`概念_{英文专名}_{中文释义}.md`
  - **范例**：`概念_Verifiable_Reward_可验证奖励.md`、`概念_FlashAttention_快速注意力.md`、`概念_Continuous_Batching_连续批处理.md`
- **规则 3：原生中文概念（无对应英文专名）**
  - **格式**：`概念_{中文规范名}.md`
  - **范例**：`概念_AI原生思维.md`、`概念_Agent三层记忆体系.md`、`概念_量化.md`

### 3. Frontmatter `aliases` 强约束与未链接提及机制
每个概念页的 YAML Frontmatter 强制维护 `aliases` 数组，至少包含：
- 英文缩写（如 `RLVR`）
- 英文全称（如 `Reinforcement Learning with Verifiable Rewards`）
- 中文标准名及常用简称（如 `可验证奖励强化学习`、`可验证奖励`）
- 历史旧文件名（保持向后兼容检索）

### 4. 存量概念全景盘点与分阶段迁移计划
全库 329 篇概念分三阶段渐进式迁移：
- **Phase 1（中英倒置纠偏，28 篇，优先执行）**：如 `概念_主成分分析_PCA.md` $\rightarrow$ `概念_PCA_主成分分析.md`
- **Phase 2（纯英文补全核心中文，67 篇）**：如 `概念_BM25.md` $\rightarrow$ `概念_BM25_最佳匹配25算法.md`，`aliases` 保留原英文
- **Phase 3（标点与分隔符统一，约 15-20 篇）**：统一清洗下划线 `_`

### 5. 自动化重命名与原子替换技术方案 (SOP)
详细规定确定性迁移脚本的执行流：
1. 构建 `old_path -> new_path` 映射字典
2. 物理重命名（保持历史轨迹）
3. 读取概念页并自动将旧名/缩写/全称去重注入 `aliases`
4. 全库扫描（`wiki/` 与 `raw/`），对 4 种双链格式（带别名与不带别名）执行精准正则原子替换
5. 同步更新 `wiki/index.md` 与 `wiki/log.md`
6. 强制运行 `uv run scripts/vault_lint.py lint` 验证 0 错误、0 死链
