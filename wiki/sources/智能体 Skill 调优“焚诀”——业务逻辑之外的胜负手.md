## 核心要点

1. **运行时视角与成分拆解**：Skill 不仅是一份静态 Markdown 指南，更是智能体主循环（感知 → 决策 → 行动 → 反馈）中的运行时交互组件。其由三种不同“物理规律”的成分构成：
   - **常驻索引（description / 聚合索引）**：每轮请求常驻上下文参与路由决策，受注意力稀释与 KV Cache 缓存前缀规律制约，必须简短、稳定且聚焦路由条件；
   - **按需知识（templates 正文）**：命中后通过 `read_file` 动态按需注入，仅在被选定时消耗上下文，要求单一职责；
   - **外部确定性约束（代码护栏）**：不进入模型上下文，由系统代码强制执行（100% 确定性保证）。
2. **意图层“分析范式”切分与黑洞意图消除**：AI 批量初创技能往往采用“一个话题一个技能”（如公告解读、估值比较等37个平铺意图），导致意图语义天然重叠、分类器系统性混淆，并产生吸走周围各类提问的“黑洞意图”（如“公司基本面”）。生产级解法是将根意图收敛为 6 个“分析范式式”二级意图（宏观策略、行业跟踪、个股研究、研究活动、研究纪要、投顾服务），将“几十选一”拆解为“六选一 + 技能内子能力路由表”，使准确率从低谷跃升至 92.50%，并使分类错误单向可收敛。
3. **意图映射配置与 Few-shot 确定性**：映射配置（`intent_skill_mapping.json`）采用 `[规则基座, 聚合索引]` 二元组，支持 Redis Pub/Sub 热更新。消融实验表明，`typical_questions` 典型问句 Few-shot 的核心价值在于建立判别锚点、买入“确定性”（兜底率从 4.59% 降至 1.08%，P95 延迟从 9552ms 骤降至 3743ms），而分类准确率的核心主力来自业务经验沉淀的判别规则。结合前置四阶段改写管道（RewriterPipeline）与 FAQ 向量化短路，实现确定性逻辑外置。
4. **三层专家套件（1 + 6 + 19）与 DRY 原则**：针对平铺技能引起的规则重复漂移与上下文腐化（Context Rot），将 37 个技能重构为三层架构：
   - **L1 基座（research-baseline）**：合规与通用铁律（唯一权威源，处处引用，禁止复刻）；
   - **L2 聚合索引（6 个）**：业务路由表与增量执行约束；
   - **L3 模板（19 个）**：单一分析范式的工作流与产出结构。
   每一层仅声明本层增量，单技能上下文由 ~6000 token 削减至 ~1200 token（节省约 80%），同时超长稳定的基座带来了极高的 Prefix KV Cache 复用率。
5. **Description 路由条件铁律与反例机制**：Description 在运行时的唯一职责是让模型判断“要不要加载我”，必须只声明“什么时候该用（Use when）”、“什么时候不该用（Don't use when）”和“产出物是什么”，坚决剔除毫无判别增量且每轮白白消耗 Token 的功能简介。近义技能错误多发于语义边界，反例（负样本）是划清边界的关键武器（缺少反例时准确率从 73% 跌至 53%，补足反例后跃升至 85%）。
6. **Bad Case 驱动五步法与“约束代码化”**：真实现场问题修复遵循五步法：
   - ① 归因分层（意图层/架构层/模板层/工程层）；
   - ② 落点选择（**确定性约束下沉为代码护栏**，如用户指定时间参数、检索上限、引用编号；语义性约束留存 Prompt；**同一 bad case prompt 修两次仍复发必须代码化**）；
   - ③ 落点唯一（跨业务入基座，业务特性入模板）；
   - ④ 配 ✗/✓ 正误双格式对例（LLM 对可模仿样本的遵循度远高于抽象约束）；
   - ⑤ 登记交付前自检清单并回填评测集。
7. **三层评测闭环与敏捷实践**：构建与三层套件匹配的评测防线：意图层（离线评测集 + 契约测试 + L0 级用例过滤全对才能发布）、技能输出层（自检清单 + bad case 回归）、端到端（独立 CLI 脚本 `eval_rag_performance.py` 多通道采集分析）。提炼三大核心实践：第一个失败就建评测（20-50个真实案例即可启动）、区分探索用 Pass@k 与上线用 Pass^k、评测集与典型问句/FAQ库同源共建。

## 关键引文

> “AI 一天能帮你生成 37 个 skill，但‘能生成’距离‘能生产’，隔着一整套工程体系——路由分得准、结构拆得省、规则写得狠、案例配得真、评测兜得住。”

> “skill 的本质，是把领域专家的隐性经验编译为 LLM 可执行的显性规则。AI 能极大加速‘编译’，但‘链接与调试’——路由、整合、调优、评测——仍然是人的工程活，也正是业务逻辑之外的胜负手。”

> “模型负责推理，外部系统负责状态和边界——skill 优化，就是不断把该外置的外置、该常驻的写短、该按需的拆开、该枚举的封死。”
