## 核心要点（Executive Summary）

1. [原文陈述] **AI 静态 Demo 页面与电商真实 C 端投放的四大鸿沟**：
   - 通用 AI“一句话生成页面”极易产生缺乏商业生产价值的“玩具 Demo”，在真实电商业务面临四大瓶颈：
     ①**渲染体系不兼容**：普通 HTML 无法支撑手淘端内性能、埋点和动态商品渲染体系；
     ②**虚假商品数据**：AI 缺乏商品供给挖掘与圈选能力，存在胡编商品数据与无法个性化推荐；
     ③**视觉水准失控**：缺少排版、材质、情绪等设计语言约束，无法达到手淘设计水准；
     ④**无法长程二次编辑**：运营对供给、坑位、样式的细粒度调整会导致局部前提破坏。
   - **方舟 AI 会场目标**：实现“想法即生成，生成即可投放”，具备内容实时策划、淘天设计水准、真实货品运营与 C 端线上投放四大核心特征。

2. [原文陈述] **业务主链路与最重要的产物（承载业务语义的 page.html）**：
   - **业务链路**：内容与供给产出（策划 Skill 挖掘人群/场景，产出《会场策划.md》与选品集 ID）→ 设计与数据分别准备（视觉 Skill 保留基准，数据阶段建立插槽与召回关系）→ 构建页面并交付（接入真实卡片装配 `page.html` 并走生码/审批/发布）；主 Agent 贯穿链路。
   - **同一份 HTML 的三维约束解耦**：
     - **视觉设计（软约束）**：`visual-design` 与 30+ 风格 Skill 守住气质与视觉层级，相框、字体与留白可自由组合，发挥创造力而非模板填空；
     - **货品数据（认知约束）**：`page-data` 建立选品、Slot 与召回认知，`data-ark-slot` 与 `data-ark-index` 直接写在卡片 `<a>` 标签上，在 DOM 上彻底解耦“视觉分组”与“供给分组”（避免为 Slot 加 wrapper 破坏 CSS Grid/Flex 布局）；
     - **生码（硬约束）**：`page-build` 与 Ark 协议规定 Section、卡片与字段装配边界。
   - **多维认知下的二次编辑**：按视觉样式、真实供给、数据投放、静态/动态文案四类对象分别调用对应 Skill 修改，混合诉求按依赖顺序处理，最终回到同一份页面校验。

3. [原文陈述] **为云端业务 Agent 设计的工作区环境（Workspace）**：
   - **状态持久化落盘 OSS 虚拟文件系统**：通过 `ls/read/write/copy/edit` 操作材料，底层按 SID 映射到 OSS 路径；会话释放不删除产物，工作进度与单次运行进程解耦；
   - **通过文件收敛业务认知范围**：通过 `page-data.json` 提供 `slotKey/aldSlotId/datasetId/cardCode` 映射，底层复杂模型关系交由业务工具处理，Agent 无需在每轮对话重建全套后端对象关系。

4. [原文陈述] **SubAgent 的收益、成本与任务拆解准则**：
   - **拆分视角权衡**：按职责拆（策划/设计/前端分离，但跨域编辑协调困难）、按流程拆（决策与执行分离，但易脱节）、**按任务拆（落在一批可验收的独立工作上，主 Agent 负责连续决策，Task 委派，Skill 提供专业能力）**；
   - **两大委派场景**：①输入输出说得清才交出去（如互联网内容挖掘、选品集创建，以实现上下文隔离）；②独立任务并行加速（洁面、修护、防晒分别创建选品集，独立查询指标并行交回）；
   - **应对信息损失**：交接采用“结论 + 执行记录路径”格式，结论进入主循环，过程沉淀为工作区可重读文件，确保后续多轮追问有据可查。

5. [原文陈述] **上下文工程深度实践与 Prompt Cache 业务权衡**：
   - **上下文重要性四层划分**：
     - **P0（核心约束）**：系统提示词、用户目标等核心执行事实；
     - **P1（关键技能）**：已加载的关键 Skill（设计风格、页面协议），全量压缩时必须显式恢复；
     - **P2（当前判断信息）**：当前 HTML、当前截图等即时结果；
     - **P3（过时可重取信息）**：历史 `read` 工具结果、早期截图等低优先级信息。
   - **Prompt Cache 真实业务挑战**：
     - 同轮对话严格仅向末尾追加消息；SubAgent 若耗时超过 5 分钟，会导致主 Agent 缓存过期发生 Cache Miss；
     - 跨轮对话中，5 分钟内快速追问重在消息恢复一致；超过 5 分钟缓存冷却后，主动执行“微压缩”，清除高占比的不重要工具结果（如 `read` 结果），以低 Token 成本冷启动，实现成本与效果的动态权衡。
   - **五层可观测体系（LLM Trace）**：Session → User Turn → 主/子 Agent Request → Tool Steps → Provider 出口网络请求，记录真实输入输出与上下文构成，辅助分析决策与打标迭代。

6. [原文陈述] **自迭代环境：质检工具设计（创造力与确定性交付的平衡）**：
   - **质检设计原则**：一个前提（不能阻碍视觉与商品运营的创造力），两个基本要求（确定性高保障交付、检测速度极快以随处调用）；
   - **确定性检测细节**：
     - 掉坑检查先确认共同父容器，区分显式缺格与末行不满；
     - 旋转倾斜卡片用变换前 `offsetWidth` 判断原始卡宽，避免把拍立得倾斜判定为不对齐；
     - 3×3 采样 + `elementsFromPoint` 检测真实图层遮挡，商品卡超阈值重叠报 error，合法设计（Bento、横滑）持续回归。
