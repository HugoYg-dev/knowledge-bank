## 核心要点（Executive Summary）

1. [原文陈述] **算法研发痛点与 Karpathy AutoResearch 原型的企业级落地困境**：
   - 算法工程师日常循环陷入“改代码—提交训练—等待—看日志—决定下一步”，长等待与多任务切换成本挤压高价值判断，日均实质迭代仅 2~3 次。
   - 2025 年底 [[entities/实体_Andrej_Karpathy|Andrej Karpathy]] 开源 [[entities/实体_AutoResearch|AutoResearch]] 原型（单张 H100 训练 50M GPT，仅靠 `program.md`、`train.py`、`prepare.py` 三文件与冻结裁判、keep/reset Git 棘轮机制两日跑出约 700 次实验和 20 个正向提交）。
   - 将其搬入企业场景时暴露出三大瓶颈：①**可信度问题**（规则全部以自然语言 Prompt 声明，模型幻觉导致执行不可信）；②**运行环境差异**（本地单机 vs 企业云端平台异步耗时训练，评价指标需体现业务差异）；③**LOOP 架构的根本局限**（keep/reset 本质是单线程串行循环，同一时刻只能维护单条时间线）。

2. [原文陈述] **五大架构设计理念与 Harness 核心定位**：
   - **高效与性价比**：利用夜间与周末闲置算力，解放人力聚焦高价值决策；
   - **与底层 Agent 基座解耦**：坚持“无状态触发 + 有状态文件”，模型升级即可无缝“搭便车”受益；
   - **系统自进化**：经验、工具与 Skill 随执行自动总结，经人机审核反哺系统；
   - **真实大闭环**：上线后 A/B 实验反馈回流业务知识库，校准离线与线上指标偏差，充当最稀缺数据燃料；
   - **可信优先与 Harness 定界**：凡能用代码表达的约束一律不放 Prompt 里；打磨特定领域 [[concepts/概念_Harness_Engineering_宿主编排工程|Harness]] 是差异化核心（援引 LangChain 实证：同模型仅调 Harness 跨领域任务提升 14 个百分点）。

3. [原文陈述] **三次架构演进：从单线程 LOOP 到 CyclicGraph Engine 图探索**：
   - **V1（把 LOOP 搬上企业云端）**：定时任务 + Shell 脚本触发单 Agent 串行跑通全链路，面临上下文爆炸与状态同步迟滞；
   - **V2（异步循环与显式状态机）**：每次触发创建全新会话，状态持久化在 JSON 状态文件，拆分为 Monitor 与 Iterator 双角色按 `phase` 互斥路由，以“无状态触发 + 有状态文件”回应数小时长周期训练的物理约束；
   - **V3（CyclicGraph Engine 图探索）**：打破单线程限制，确立 **Spawn-Converge** 机制——决策层主 Agent 拆解 3~4 个互斥差异化假设，派发给隔离子 Agent 并行修改与提交训练，主 Agent 汇总对比各独立结果并决策收拢；配套状态机异步触发与断点恢复。
   - **图架构效能跃升**：在同建模项目上，LOOP 架构 10 次迭代耗时 3 天（0.14 次/h）未突破，切换图架构后 12 次迭代仅耗时 4.7 小时（2.55 次/h）即达成目标，迭代速度相差 18 倍；收益来自正交并行提升信息获取量约 3 倍、汇总分发提升有效决策数、边界探针及单变量控制。

4. [原文陈述] **垂直场景深度耦合：业务知识库 + 渐进式调研机制**：
   - **业务知识库**：新项目提供建模目标、样本口径、历史结论与约束边界，作为系统的“入职培训”；
   - **三层调研机制**：①初始化调研构建方向池；②渐进式调研按需动态补充；③**强制调研逃逸机制**：当指标边际提升缓慢、连续多轮在同一方案打转时强制切换维度并重新调研，避免局部最优空转。

5. [原文陈述] **全链路可信度防御体系与二级人机校验 Skill 机制**：
   - **两类错误分类治理**：认知层幻觉（证伪方向写入状态文件硬约束直接代码跳过） vs 执行层偏差（幂等化工具、返回值结构化强校验、区分代码故障与基础设施故障）；
   - **原始证据优先**：保留每轮探索的原始指标提升和代码 diff 原件，将物理训练事实作为不可绕过的校验锚点，切断错误复合放大；
   - **上下文隔离与交叉验证**：子 Agent 上下文互不知情验证假设，主 Agent 置信度低或方向性决策时触发交叉验证；
   - **二级人机校验 Skill 草稿机制**：执行踩坑经验自动整理为 Skill 草稿，经“系统初筛 + 人工审核”晋升为正式 Skill 写入工具集，成功应对数百次参数服务器异常等基础设施故障，形成反幻觉晋升链。

6. [原文陈述] **真实业务效果与 AutoML 本质区别**：
   - 在两个结构、目标与场景均不同的建模项目上，单任务耗时较人工基线分别减少约 85% 与 83%；
   - 系统自主推导出的优化方案（不在任何参考论文中）推全上线并取得实际线上收益；多目标项目全部 12 个预估目标均超越人工基线；
   - **与传统 AutoML 的本质差异**：传统 AutoML 预设答案在固定搜索空间内，而 AutoResearch 具备自主生成假设、证伪错误框架并主动推导扩展新候选方案的跃迁能力。

7. [原文陈述] **适用边界与局限性**：
   - 适用三要素：具备明确可量化指标、单次实验成本可接受、实验结果可逆；
   - 三大现实局限：强依赖底层训练算力基础设施、垂直经验跨项目迁移存在局部泛化幻觉风险（需人工卡点）、“为什么有效”的归因解释可解释性仍属慢变量。
