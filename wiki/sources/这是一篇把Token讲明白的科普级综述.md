# 来源摘要：这是一篇把"Token"讲明白的科普级综述！

- **来源信息**：Datawhale / 谷歌等20+机构32位学者综述（2026-10-08）
- **核心议题**：系统阐释大模型底层“认字”机制（分词与 Token 化），剖析为什么模型在数字母（strawberry 有几个 r）、多位数算术等简单任务上会频频出错，并探讨 BPE 贪心合并算法、语言计费不平等、词表复用生态与字节级（Token-free）替代路线。
- **论文出处**：Alphaxiv 综述《Tokenization Survey for Modern NLP》（2609.tokenization-survey-modern-nlp，共 154 页）

## 核心要点

1. **模型读到的不是字符，而是字块编号（Token IDs）**：
   - 文本进入模型前必须经过分词器（Tokenizer），将字符序列切分为带编号的字块碎片（Token）。模型底层的矩阵运算接收并预测的完全是数字代号，而非字母或汉字本身。
   - 常见词（如 `strawberry`）常被直接打包为一个完整 Token 或少数大块，内部字符结构被彻底掩盖。模型从未逐字母读过该词，因此无法准确统计特定字母数量；若强行替换其中字母，熟悉的拼图被打碎，模型理解难度剧增。
   - 分词导致“表意一致但编号迥异”：如 `intelligence`、`"intelligence"` 与 `intelligent`，或句子末尾多出一个空格，切分出的 Token 序列完全不同。

2. **主流分词算法机制与局限（以 BPE 为核心）**：
   - **[[concepts/概念_BPE_字节对编码|BPE（字节对编码）]]**：从单个字母或字节出发，通过统计海量语料中相邻字符对的共现频率，反复将最高频的相邻对合并为新字块，直至达到预设词表大小。
   - **贪心策略非全局最优**：BPE 每一步只挑局部最高频对合并，论文通过实验证明存在非贪心合并方式能切出比 BPE 更短的序列。
   - **其他主流算法**：Unigram（自顶向下反向剪枝，删除对整体概率影响最小的词）与 WordPiece（基于对预测下一个词的似然增益进行合并，BERT 所用）。

3. **打包分词付出的四大代价**：
   - **能力缺陷（算术与结构感知受损）**：现代模型预分词常按从左往右每三位切分数字（如 `8675309` 切为 `[867] [530] [9]`），与人类竖式加减法“从右往左进位借位”逻辑相悖，个位数被孤立，严重破坏数位权重感知；探针实验表明模型对 Token 内部组成的感知不完全。
   - **成本与公平性（低资源语言惩罚）**：英文因高频词表充裕被高度压缩，而非拉丁语系和低资源语言缺乏预留高频词，被切得极其零碎；由于 Transformer 注意力计算开销随序列长度平方级增长（$O(N^2)$），生成同等语义内容时低资源语言消耗的 Token 量与计算开销成倍增加（如生成《世界人权宣言》换算国民平均时薪支付成本，缅甸与美国相差 54.3 倍劳动时间）。
   - **安全与攻击面（Glitch Tokens 与编码隐蔽注入）**：
     - *Glitch Tokens（如 SolidGoldMagikarp）*：因分词器语料与大模型预训练语料不完全重合，词表中收录的冷门长字块未能在上下文中充分学习，其嵌入向量处于随机未初始化状态，触发时可导致模型行为失常。
     - *隐蔽字符注入*：利用西里尔同形字母替换拉丁字母（如西里尔 `а` 替拉丁 `a`）或插入零宽连接符，肉眼无差异但彻底改变底层分词，绕过安全敏感词过滤。
   - **生态高度同质化与垄断**：
     - Hugging Face 扫描普查显示，**94% 的模型所用的分词器在底层逐字节完全复制于社区已有模型**；下载量第一名仍为 2018 年发布的 BERT 分词器（占历史下载量的 23.2%）。
     - 少数厂商反向操作：如 Anthropic Claude 4.7 将词表从 ~49,000 缩减至 ~16,000，采用类似动态规划最短路径切分，主动剔除未学透的冷门字块以收窄攻击面。

4. **无分词（Token-free）前沿替代路线**：
   - **纯字节模型（Byte-level，如 ByT5）**：词表仅需 256 个基础字节单元，天然覆盖全世界字符与生僻符号，零 OOV 问题；但序列长度成倍膨胀，自回归推理延迟居高不下。
   - **动态边界切分（如 Meta BLT）**：让模型在读取字节流时实时预测下一个字节的信息熵，在信息量陡增处动态下刀确定词界。
   - **文本视觉化渲染（如 PIXEL）**：将文本渲染为图像输入视觉 Transformer，彻底绕过字符编码与词表，在 22M 参数下语言理解打平 86M 的 BERT；挑战在于自回归生成端需要图转文。
   - **未来三大发力点**：更好的分词器 Scaling Law、针对子词缺陷的针对性补偿算法、更健全的分词鲁棒性评测基准。
