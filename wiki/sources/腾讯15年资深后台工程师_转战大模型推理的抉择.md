## 核心要点

### 1. 资深后台工程师的心态归零与战略抉择
- **技术抉择**：作者在腾讯深耕搜索后台与搜索中台 15 年并晋升 T12。面对 AI 工业革命浪潮，选择放下资历与管理包袱，以“零级新人”归零心态切入大模型推理工程。核心逻辑在于：无论上层应用或 Agent 形态如何演变，算力与推理加速等基础设施永远是不可或缺的底层基石。
- **管理者的困境与破局**：技术浪潮面前，技术管理者容易陷入“深度不足流于表面”或“管理滑坡”的双重困境。作者主张真正优秀的组织崇尚“以事为先”和纯粹的工程师文化，决定个人价值的是正在解决的具体问题而非头衔。对于资深技术人，亦可选择由通用 Infra 逐步渗透至 AI Infra 的演进路线。

### 2. 大模型推理工程体系与三层解耦
- **核心矛盾与资源置换**：推理工程的核心矛盾是算力、显存与通信三者的权衡。[[concepts/概念_LLM推理两阶段|Prefill 阶段]] 为计算密集型，Decode 阶段为显存带宽密集型。[[concepts/概念_KV_Cache_键值缓存|KV Cache]]、[[concepts/概念_连续批处理|连续批处理 (Continuous Batching)]]、Prefix Cache、张量并行（TP）等优化，本质上都是在硬件物理约束下，以最低成本置换更高的吞吐量与更低的时延。
- **评估体系与关键指标**：顶层业务目标（功能、性能、成本、稳定性），中间层量化指标（TTFT 首字延迟、TPOT 词间生成延迟、QPS、TPS、并发数 Concurrency 及单 Token 成本），底层具体技术手段。
- **工程分层架构**：
  1. **业务层**：负责推理系统与上层业务对接，包括推理服务 SDK、推理平台、服务部署与监控、业务定制的请求流量调度。
  2. **调度层**：模型推理运行时载体，直接决定系统核心性能。落地分布式并行、Prefix Cache、Overlap Scheduler、Continuous Batch、Chunked Prefill、[[concepts/概念_推测解码|推测解码 (Speculative Decoding)]] 等核心优化。
  3. **算子层**：负责高性能基础计算单元实现，聚焦单点计算性能（QKV 计算、Normalize、Linear 矩阵乘）。

### 3. 前沿优化方向与自检实战
- **关键优化主题**：
  - **PD 分离（Prefill / Decode 解耦）**：将计算密集的 Prefill 节点与访存绑定的 Decode 节点分离部署，消除资源争抢，大幅提升硬件利用率与吞吐。
  - **分布式 KV Cache**：针对多轮交互与长上下文场景，提升 Prefix Cache 跨节点命中率，降低重复 Prefill 开销。
  - **推测解码（Speculative Decoding）**：充分利用 Decode 阶段算力未饱和的特性，利用小模型草稿或单模型机制提升吞吐。
- **工程实战自检三题**：
  1. **同批次共享前缀注意力优化**：针对搜广推场景下同 Batch 内多请求具有公共前缀（如 `user_info + doc_N`），需融合因果掩码构造、KV Cache 申请使用、[[concepts/概念_FlashAttention_快速注意力|FlashAttention]] / FlashInfer Kernel 接口与 GPU Thread Block 特性，消除冗余 Prefill 计算。
  2. **Beam Search 工程实现**：面临多候选路径的 KV Cache 共享复用、高宽度（如 BW=1024）下大词表（$1024 \times \text{Vocab}$）的高性能剪枝、推荐业务合法 DocID 的约束解码，以及小众功能与主流框架的无缝结合。作者在 [[entities/实体_SGLang|SGLang]] 上实现 SOTA 性能的 Beam Search 并成功合并入官方 v0.5.19。
  3. **模型结构演进认知**：理解 MLA（多头潜在注意力）、HCA/CSA、混合架构、DSpark 推测解码等算法创新与工程优化的深度绑定。

### 4. 通用 Infra 向 AI Infra 与 Agent Infra 的演进分野
- **传统工程经验依然是底座**：大模型 API 服务的底层依然依赖传统分布式微服务、RPC、存储、全链路可观测、容量规划、发布调度与 CI/CD 体系。
- **系统设计思想的同源迁移**：
  - PagedAttention 借鉴了操作系统虚拟内存页表与 Block Table 映射离散物理页的思想；
  - 模型并行（TP/CP）继承了传统分布式系统的拆分计算与分摊负载思想；
  - CUDA Stream 对应 CPU 多线程并发；
  - 分布式 KV Cache 对应分布式存储系统的分片与生命周期管理。
- **服务范式跃迁：小卖部模式 vs 旅馆模式**：
  - 传统后台为 **“小卖部模式”**：短请求、无状态、低延时、即调即走、资源即时释放。
  - Agent 服务为 **“旅馆模式”**：多轮交互、长耗时、有状态、长生命周期；会话持续驻留、状态频繁变更，需要记忆管理、长会话调度、工具沙箱隔离与可观测治理。
