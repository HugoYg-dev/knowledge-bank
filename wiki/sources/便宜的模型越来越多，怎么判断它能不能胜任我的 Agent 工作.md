# 来源摘要：便宜的模型越来越多，怎么判断它能不能胜任我的 Agent 工作

## 来源元信息
- **标题**：便宜的模型越来越多，怎么判断它能不能胜任我的 Agent 工作
- **作者**：澄潭（阿里云 AgentCore）
- **发布渠道**：阿里云 AgentCore 微信公众号（收录于开源项目 Alibaba Cloud AI Agent Handbook 第 9 章）
- **发布日期**：2026-11-03
- **原文链接**：https://mp.weixin.qq.com/s/gjzWFqGJt29m_17B37wXVQ
- **开源项目**：HiRoute（https://github.com/higress-group/HiRoute）

## 核心要点

1. **推理成本骤降与“智价比”衡量口径**：
   - 引用 Epoch AI 报告《The plunging price of thought》：2023 年以来达到相同能力水平的模型成本平均每季度下降约 47%（每年降至原来的 1/13）。
   - 但低价模型完成任务通常消耗更多 Token，且若在 Agent 关键决策步骤出错，造成的排查、返工与方案推倒重来代价极大。因此必须确立**“智价比”核心指标：在同样的验收标准下，完成一件事总共花多少钱**，核心命题转变为“在自己的工作链路中，哪些步骤可以安全交给便宜模型”。

2. **场景定候选 vs 步骤定模型（动态难度感知）**：
   - 传统按场景固定模型的粗粒度分流存在缺陷：复杂场景（如技术选型）中包含大量简单的文本整理与核验，而简单场景也会突发复杂决策难题。
   - HiRoute 消息系统技术选型实验表明：将资料搜集与整理交给低价模型、关键选型判断交给主力模型，产出质量与全程主力模型一致，而任务总成本仅为后者的 1/12；反之全程低价模型在关键选型中错误率高达 66.7%。
   - **工程范式**：场景层仅负责定义“候选模型范围与验收质量标准”，具体每一步调用哪个模型组，必须推迟到该步骤动态评估。

3. **轮内模型锁定与前缀缓存（Prefix Cache）协同纪律**：
   - Agent 任务往往涉及连续几十次工具调用与模型交互，频繁跨模型切换会导致共享上下文的前缀缓存（Prefix Cache）完全击穿。
   - HiRoute 确立严格的缓存保护纪律：**在一轮之内（Turn）锁定模型不变，仅在用户输入新消息、上下文重构或发生压缩时重新评估**。实测单轮 21 次连续调用完全留在同一模型，前缀缓存命中率接近 90%，有效兼顾了动态路由与缓存经济性。

4. **通用榜单局限与“边用边评”证据收集**：
   - SWE-Bench Pro 实验表明头部模型在从未公开的私有代码库中胜任率骤降至 17.8%，通用榜单无法反映私有业务表现。
   - 面对频繁发布的新模型，采用“边用边评”渐进式接入策略：先仅把最简单的步骤分派给新模型，并以用户下一条消息的直接反馈作为胜任证据（用户明确否定即为失误证据），逐步积累置信度。

5. **System One 三问拆解与程序化阈值裁决**：
   - 直接让决策模型面对复杂 Prompt 和策略主观选组极不稳定，容易产生系统性偏差（过分激进或过分保守）。
   - HiRoute 提出 **System One 三问拆解机制**，在一次轻量请求中分别回答：
     1. 上一步做得怎么样？（给出胜任度评分）
     2. 这一步有多难？（给出简单概率）
     3. 上一步的问题会不会带到这一步？（判断已知未解决问题是否继续适用）
   - 贯彻**“让模型回答问题，让程序做决定”**原则：决策模型仅输出标量判断，由确定性程序根据预设阈值裁决模型组，准确率从 50%–67% 大幅跃升至 88%–100%，单次决策耗时仅 0.5–1 秒。

6. **自适应放手与收回的非对称统计门槛**：
   - 设定严格的自适应调优统计门槛：
     - **建议多放手**：至少积累 30 个打分步骤、覆盖 ≥3 个会话、打分步占比 ≥60%，且达标率 ≥85%；
     - **建议收回**：至少 30 个步骤中达标率 <70%（收回门槛显著宽松，确保快速止损）。
   - 任何策略阈值调整前，均通过历史真实会话日志离线回放评估影响，确认无误后方可发布。

7. **从底层模型路由到 Super Agent 任务路由延伸**：
   - 结合 DeepSeek Super Agent 架构原型（常驻 Router 负责协调分派，独立 Worker 负责执行），HiRoute 扩展出任务路由能力。
   - 用户日常使用的 Agent（如 Hermes、OpenCode、OpenClaw）作为 Router 负责解析任务并分派给已绑定的执行计划（如 Pi 负责资料、Qoder CLI 负责编码）；通过 `hiroute worker exec --no-wait` 启动并行执行，执行完毕后通过 `notify_on_complete` 异步回调通知 Router 汇总结果。

## 关键引文

> “智价比：在同样的验收标准下，完成一件事总共花多少钱。”

> “难度是一步一步变化的，不是一个场景对应一个值。复杂场景里有大量简单的活，简单场景里也会突然冒出难题。”

> “把资料整理交给便宜的模型、关键判断交给主力模型，关键判断的质量和全程用主力模型一样，整个任务的成本只有后者的十二分之一左右。”

> “场景这一层决定'有哪些候选模型、按什么标准验收'，具体每一步用哪个模型，要到这一步再判断。”

> “三个问题：让模型回答问题，让程序做决定。它的价值不在于让某个模型变得更聪明，而在于把容易想偏的复合判断拆开，让结果不再依赖某个模型恰好擅长这种判断。”
