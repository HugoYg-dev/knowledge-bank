## 核心要点

### 1. 痛点背景与预测判断模型的演进史
- **业务痛点**：在构建复杂 AI Agent 时，存在大量高频状态机流转需求（“记忆是否相关”、“请求交给哪个工具”、“是否需人工介入”）。传统通用 LLM 做出简单判定前总需生成数百个思考 Token 和冗长 JSON，消耗大量计算与延迟。[[entities/实体_Jev|Jev]] 切中了“跳过生成、直接输出概率”的刚需。
- **历史前身**：预测判断模型早于 GPT 产生——2018 年 BERT 的 Encoder-only 双向表示与单层分类器；2019/2020 年 OpenAI 基于人类偏好的奖励模型（Reward Model）；2023 年《Let's Verify Step by Step》的过程验证器（PRM）；2025 年 Galileo Luna-2“单 Token 分类器”；2026 年 Skywork-Reward-V2 等。“继承语言模型理解能力但不生成文字”并非 Jev 独创。
- **Jev 的差异化**：
  1. 追求对真实世界事件概率的通用性（通过 [[concepts/概念_RLCD校准决策强化学习|RLCD]] 进行概率校准，而非仅拟合人类偏好）；
  2. 极致压榨并行计算，支持单次请求内针对同一份材料并发执行上限 250 道独立问题。

### 2. 接口形态与三大约束原语
- **输入结构**：
  - `State`（状态）：共享的长篇背景材料（如客服日志、投诉记录）。
  - `Questions`（问题）：针对该 State 同时提出的若干独立问题，互不干扰。
- **三大标准化原语**：
  - `Noul`（是非题）：直接返回 0~1 之间的单一置信概率。
  - `Choice`（选择题）：给定多个候选项，返回各自归一化的概率分布。
  - `Score`（打分题）：返回各等级概率分布与最终加权期望分。
- **推测性并发（Speculative Fan-out）**：鼓励客户端在入口一次性将所有可能相关的多维判断（如“是否故障”、“严重程度”、“分派部门”）全量并发查询，计算后由业务代码按逻辑剪枝丢弃无用结果。

### 3. Jev 架构四部曲反向解密（基于黑盒测试与开源复刻 Kev / NanoJev / minojev）
1. **第一站：共同信息只读一次（State 共享）**：
   - 外部探测显示多题目计费仅增加问题自身 Token，响应延迟在百题内基本呈水平线；
   - 底层机制：一次性执行 State 的 Prefill 计算，将其 Key/Value 状态冻结在 [[concepts/概念_KV_Cache_键值缓存|KV Cache]] 中，后续所有并行问题直接共享复用该缓存，消除重复 Prefill 开销。
2. **第二站：题目物理隔离与并行拆分**：
   - 暗号实验（问题 A 塞入暗号，问题 B 无法识别，但在 State 中可识别）证实多题目间存在强物理隔离；
   - 实现方案一：**注意力掩码（Attention Masking）**，通过掩码矩阵强行将相邻题目的注意力权重置零；
   - 实现方案二：**独立分支复用（Forking KV Cache）**，读完 State 后以冻结缓存为基点分叉出数十条独立推导路径，特别适配循环与混合注意力架构底座（如 Qwen3.5）。
3. **第三站：选项交互计算（否定线性头，引入相互拉踩机制）**：
   - 插入无关干扰项（如“坏天气”）会改变已有选项间的相对赔率，彻底推翻了“独立线性头（Linear Head）+ Softmax”的黑屋盲审假设；
   - 方案一：**指针头（Pointer Head，如 Kev）**，同场群面模式，模型通读所有选项后，在末尾位置作为全局语境指针指回各候选打分；
   - 方案二：**候选间注意力模块（Inter-candidate Attention Module，如 NanoJev）**，各选项先抽取特征向量，再由专用注意力小网络集中比对。使选项本身能够作为解题语境线索（如区分粗粒度国家与细粒度城市）。
4. **第四站：无自回归概率提取**：
   - 候选项增至数百个时耗时无等比拉长，证实跳过了逐 Token 自回归解码，直接在指定首位置 Logits 或专用头抽取概率。

### 4. RLCD 后训练、数据合成与校准机制
- **训练数据合成**：使用 DeepSeek V4.1 合成上百种业务场景试题，要求教师模型多次检验一致性；Kev 基于真实金融投诉（5,219 篇）制作题目；构造**成对陷阱题**（仅变动关键主体导致结论反转），防止模型通过 Reward Hacking 投机硬背。
- **训练方式与 Gap**：当前开源复刻多采用 LoRA + 教师蒸馏（交叉熵损失），本质上学习的是教师大模型的概率分布，而非 RLCD 声称的客观世界事实概率。
- **概率校准实测**：Jev 在 1200 道 MMLU 测试中校准误差仅 0.031（86.7% 准确率报 83% 把握，32% 准确率报 30% 把握）；开源复现常采用的**温度校准（Temperature Scaling）**仅是全局下调整体自信度，并未提升模型区分自身边界的辨别力。

### 5. Jev 的适用边界与 Agent 经济账
- **两道难以逾越的坎**：
  1. **困难多步任务严重跛足**：多条件、连续查找证据、日期与数字比较严重失真（JevBench 困难题准确率 74.1% vs DeepSeek V4.1 Flash 95.0%；两步应用题正确率暴跌至 32%）；
  2. **表示稳健性与领域泛化脆弱**：受输入信息呈现位置严重干扰（关键关系从文本开头移至中间，正确率从 80.5% 腰斩至 40.9%）；新封闭测试集准确率暴跌至 36.7%；跨领域迁移（软件安全检测 AUROC 从 0.851 降至 0.605）。
- **工程定位与经济账**：
  - 适合定位在**标准明确、证据集中、判断结果可被代码/后续步骤验证纠正**的高频前置分流节点；数学计算与日期比较交由确定性代码；
  - **警惕延迟与成本倒挂**：若加入 Jev 后后续仍需无条件调用主模型，不仅无法加速，还会因增加一次网络与模型调用导致 Agent 端到端总延迟翻倍（实测 649ms -> 1087ms）且费用增加数倍。
