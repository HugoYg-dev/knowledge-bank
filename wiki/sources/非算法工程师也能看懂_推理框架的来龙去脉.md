# 非算法工程师也能看懂，推理框架的来龙去脉

## 来源信息
- **标题**：非算法工程师也能看懂，推理框架的来龙去脉
- **作者**：望宸（阿里云 AgentCore）
- **发布日期**：2026-10-21
- **原文链接**：https://mp.weixin.qq.com/s/gA51FfYoAedGGWYnqRNFiw

## 核心要点

1. **推理框架的定位与“五维权衡”（快、多、省、稳、准）**：
   - 模型从预训练、后训练、评测到部署上线，训练是一次性投入，而上线后的推理是持续性算力支出。
   - 推理框架是模型上线后连接硬件的中间件层，负责将模型加载到不同硬件和软件环境、组织前向计算与请求调度。
   - 框架的核心能力体现在五个相互制约的维度：**快**（首字时延 TTFT 极短、生成流畅）、**多**（单位硬件并发吞吐高）、**省**（显存算力用足、缓存复用摊薄调用成本）、**稳**（流量高峰、超长请求与故障时高可用）、**准**（对齐基座能力、格式符合要求、输出可复现）。
   
   ![模型生命周期与推理框架定位](https://mmbiz.qpic.cn/sz_mmbiz_png/3Xrv1bwNrT6TfRcHsicw4X5ic9TeRot1hI5NN1RKIKYW1NRGlsVhI3GKVfusCT7Q9t8rFSdOHVicsYRGqibdS6ZDTT4gFbY1M2yLuUWTd1ILtko/640?wx_fmt=png&from=appmsg&tp=webp&wxfrom=5&wx_lazy=1#imgIndex=0)

2. **训练框架 vs. 推理框架：在线服务系统的本质转变**：
   - 训练框架（如 PyTorch、Megatron-LM）关注前向计算+反向传播更新权重、静态批量数据与收敛效果；
   - 推理框架只做前向计算（权重固定不变），面对的是长短不一、随机到达的在线并发请求，本质是一个类似数据库与 Web 服务器的高性能在线调度系统，调度的核心资产是昂贵的 GPU 算力与显存资源（权重 + [[concepts/概念_KV_Cache_键值缓存|KV Cache]]）。

3. **为什么“写”比“读”贵？Prefill 与 Decode 的物理对立**：
   - **[[concepts/概念_LLM推理两阶段|Prefill（预填充）]]**：一次性读入全部 Prompt，所有输入 Token 并行计算，充分调动 GPU 浮点计算单元，属于**计算受限（Compute-bound）**；
   - **[[concepts/概念_LLM推理两阶段|Decode（解码）]]**：自回归串行逐字生成，每生成一个 Token 必须将模型全量权重完整加载遍历一次，但仅完成单步极小计算，瓶颈在于显存访存带宽，属于**访存带宽受限（Memory-bound）**；
   - 输出 Token 占用显存带宽时间远长于输入 Token，且必须单字串行生成，导致云厂商 API 计费中输出价格通常是输入的数倍。

4. **智能体复杂负载对推理框架的全新倒逼**：
   - 智能体执行任务伴随多轮多步的工具调用与环境交互，单次任务可能调用模型十数次；
   - 请求负载表现出典型特征：**输入长、输出短、前后轮次上下文高度重叠**。端到端耗时为各步耗时累加；
   - 倒逼推理系统从“比拼单机谁算得快”升级为“比拼谁能少算（复用既有中间结果）”，**缓存命中率直接主导了智能体的经济性与响应体验**。

5. **一个请求的内部旅程：推理框架六大环节架构解构**：
   
   ![推理框架内部请求处理全流程](https://mmbiz.qpic.cn/sz_mmbiz_png/3Xrv1bwNrT6CaLezib5ibG7Kce5X5ElhRcdCdnCOefnJlOx35T7ia7ouh0r06hlumtNS8ZWGlBy2JPTUduib0bfib0Nl1b6wT10xiaibiaqVbK7su5A/640?wx_fmt=png&from=appmsg#imgIndex=8)

   - **入口接入层**：统一多协议格式，依据各模型规范组装对话模板（Chat Template），执行 Tokenizer 编码与安全特殊标记转义拦截，输出端反向解析结构化数据与流式回传。
   - **调度层**：基于[[concepts/概念_连续批处理|连续批处理 (Continuous Batching)]]在每步生成边界动态插拔请求；采用**分块预填充（Chunked Prefill）**将超长 Prompt 切片穿插在 Decode 步之间，消除首字延迟对存量请求的卡顿冲击；采用 CPU-GPU 异步调度消除空转。
   - **执行层**：多卡并行（TP、PP、DP 及面向 MoE 的 EP 专家并行与热门专家副本），搭配底层融合算子（如 [[concepts/概念_FlashAttention_快速注意力|FlashAttention]]）、低精度量化计算（FP8/INT4）与 CUDA Graph 录制回放以消除算子启动开销。
   - **缓存层**：借助 [[concepts/概念_PagedAttention_分页注意力|PagedAttention]] 虚拟内存分页彻底根除显存碎片浪费；落地前缀缓存（Prefix Caching）跨请求复用公共 Prompt；构建显存-主机内存-分布式多级缓存体系（如阿里云 Tair KVCache）。
   - **集群层**：推动 **[[concepts/概念_PD_预填充解码分离|PD 分离 (Prefill-Decode Disaggregation)]]** 部署架构，将计算密集的 Prefill 节点与带宽密集的 Decode 节点硬件物理隔离，KV Cache 经高速网络跨节点同步；实现智能路由与弹性容错。
   - **采样与输出层**：通过 Temperature/Top-p 控制随机性；利用“批不变确定性推理”保障评测与强化学习概率一致；通过语法规则编译实现**结构化输出（Structured Outputs）**排除非法 Token，保障工具调用格式 100% 正确；集成[[concepts/概念_推测解码|推测解码 (Speculative Decoding)]]利用小模型草稿并行验证显著加速。

6. **开源生态演进三大趋势与人群落地**：
   - **三大演化方向**：从单机引擎（vLLM、SGLang、TensorRT-LLM）走向分布式集群调度（Dynamo、llm-d、Mooncake）；从通用实现走向模型与推理协同发布（如 DeepSeek 开源 DeepInfer、FlashMLA，阿里 RTP-LLM）；从英伟达单一硬件走向昇腾、昆仑芯、沐曦等国产芯片多元支持（通过硬件插件与 Triton/TileLang 抽象）。
   - **典型落地人群**：不仅赋能模型厂商、云厂商与自建机房私有化部署企业，更直接指引应用开发者编写前缀稳定的“缓存友好型”提示词，并在后训练（RL 生成、数据蒸馏）与端侧轻量运行（llama.cpp、Ollama）中发挥核心支柱作用。
