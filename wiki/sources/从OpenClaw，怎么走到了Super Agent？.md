# 来源摘要：从OpenClaw，怎么走到了Super Agent？

## 来源元信息
- **标题**：从OpenClaw，怎么走到了Super Agent？
- **作者**：spike（腾讯游戏数据团队负责人）
- **发布渠道**：腾讯程序员 / 腾讯技术工程
- **发布日期**：2026-11-03
- **原文链接**：https://mp.weixin.qq.com/s/R8v1fxHpErVHq1o6euSroA

## 核心要点

1. **Bot 与 Working Agent 的“双向奔赴”演化逻辑**：
   - 年初产品受 OpenClaw 启发以聊天 Bot 为主（入口轻便、新手容易上手）；年中逐步转向 IDE 与桌面类 Working Agent（如 WorkBuddy，贴近实际工作环境、便于处理具体交付物）；近期两类形态开始双向融合：Bot 类补齐工作台、连接器与文件工具，Working Agent 则扩展移动端、群聊入口与多端协同。
   - 驱动该演化的是两个朴素需求：① 智能体要把任务做好，必须无限接近人的实际工作环境；② 上下文与人机磨合（Coach）越深，用户越希望随时随地能调动它，并将其成熟能力共享给他人复用。

2. **工作环境壁垒与上下文工程的深层价值**：
   - 给 Agent 一台云端机器并不等同于在同一环境工作。若本地代码仓库、即时通讯群聊讨论、设计决策取舍无法无缝衔接，Agent 仍处于孤立状态。
   - 任务成败往往不取决于单句 Prompt 的华丽程度，而取决于 Agent 在执行时能否拿到需求背景、口径定义与被否决方案的历史背景，这凸显了 [[concepts/概念_上下文工程]] 与 [[concepts/概念_Harness_Engineering_宿主编排工程]] 的决定性作用。

3. **入口多态性驱动高质量上下文闭环**：
   - 将 Working Agent 接回微信/移动端并非仅为了提供“远程遥控器”，更核心的价值在于“讨论与新背景的即时回流”。用户在移动状态或群聊沟通中产生的条件变更与粗糙想法能直接注入原工作链路，避免回到电脑前因信息遗忘导致的认知断层。

4. **从个人自用到团队协同的能力交付范式**：
   - 团队赋能不再局限于“分享一份静态 Prompt”，而是将专家已经调优好的知识、工具和数据环境打包为成熟 Agent 服务。专业人员在后台持续维护 Agent 能力，普通使用者在自身熟悉的会话入口输入具体业务需求并参与验收，实现认知门槛解耦。

5. **环境共建：让 Agent 参与自身 Harness 与能力扩展**：
   - 当 Agent 执行受阻时，单靠追加“你要认真一点”等提示词收效甚微，根因通常在于环境缺失或工具失配。
   - 借助类似 [[entities/实体_DeepSeek_Harness]] 的 Creator mode 或 Mods 机制，用户可以通过自然语言与具备执行能力的 Agent 协同安装插件、配置工具链与调试交互界面，实现人机协同共建运行环境。

6. **成熟 Agent 辅导新 Agent（Mature Agent Coach）机制**：
   - 在孵化细分场景的新 Agent（如日常事项追踪）时，无需从零手动配置；可由已深度熟悉用户习惯与评测标准的成熟 Agent 担任教练（Coach），负责测试新 Agent、对比来源、排查偏差并调优策略，人类仅需在关键裁决点（如价值取向、介入尺度）进行把关。
   - 关键工程纪律：必须让新 Agent 独立完成任务演化验证，严禁老 Agent 越俎代庖；同时在面向团队分发时，必须严格隔离私人记忆与通用专业能力。

7. **通向超级智能体（Super Agent）的架构收敛**：
   - 无论是从通用聊天 Bot 补齐执行外壳，还是从垂直 Working Agent 延伸外部入口，产品终局都在探索“能在具体长程任务上高可靠代表用户行动的智能体”。常驻协调入口与离线执行环境的结合，直接催生了 [[concepts/概念_Super_Agent_超级智能体]] 与 [[concepts/概念_Personal_Agent_个人智能体]] 范式。

## 关键引文

> “Agent要把事情做好，就需要更接近人的实际工作环境。”

> “而如果上下文更多，人的coach也更多，Agent越来越好用，人就越希望随时能找到它，也希望把它的能力交给别人用。”

> “入口方便，也会影响积累的质量。越容易继续聊，越愿意把刚发生的变化、还没整理好的想法交给它；这些背景留下来，下一次它又更容易理解我。”

> “能调整的不只是它说话的方式，还包括它取得什么背景、调动哪些工具、在哪个环境里做事。”

> “不一定要再搭一个很复杂的系统，可以先让已经用顺的Agent承担这个角色：帮忙准备、测试、查问题、修改，再把需要我判断的地方拿回来。”

> “什么样的Agent，能够在具体事情上，越来越准确地代表我去做事？”
