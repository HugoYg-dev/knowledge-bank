# AI 原生思维——像训练大模型一样训练自己

## 核心要点

### 1. 找需求：盯住模型能力的边界线（Demand on the Boundary）
真正的 AI 产品机会诞生在模型能力边界线刚好扫过的地方。判断一个需求是否值得投入必须连过三问：
- **痛点够不够硬**：是否是真实且强烈的刚需；
- **自己是不是高频用户**：只有自己天天用，才能构建出紧密的反馈闭环并感知真实体验；
- **AI 是不是刚好够到**：以 Nano Banana 城市天气画图提示词为例，早期版本需人工繁琐输入城市与天气细节，传播受限；随着模型内置搜索能力解锁，提示词精简为仅需输入一个城市名即可生成，瞬间引爆全网。需求始终都在，但体验差一步、命运差十倍，核心在于能力边界的顺风扩展。

### 2. 判边界：能力、成本与价值的三关过滤
一个 AI 需求在推进前必须经历三维边界审视：
- **能力边界（动态）**：同一个想法在不同时期命运截然不同（2023 年 AutoGPT 因模型长程推理能力欠缺和高成本而打转失败，2025 年 Manus 能力刚好够到而火爆）。产品落地准则是“搭架子等模型”：现在能做的立刻做，半年后能做的搭好骨架等待模型顺风进化，长期做不了的工程打补丁或直接不做；
- **成本边界（动态）**：Token 单价下降但 Agent 模式下调用总量激增（成本 = 调用次数 × 每次 Token 量 × 单价）。在真实优化中，通过让模型输出对它更友好的纯文本和 HTML，替代臃肿嵌套的结构化 JSON，把复杂 Diff 对齐解析交由确定性程序，实现调用次数骤降 60% 以上；
- **价值边界（静态）**：锚在人性上而不随模型升级移动。明确区分用户买的是“确定性结果”还是“结果背后的人与情感”，严禁大规模生产无意义的“AI 垃圾”。

### 3. 最小验证：高保真原型与非舒适区语言突破
为了避免项目陷入半成品坟场，必须推行极速最小验证，让坏想法死得早：
- **高保真原型压缩周期**：借助 Claude Design 等能力直接生成可点击的高保真原型，跳过手写代码，将数周的原型反馈周期压至数小时；
- **非舒适区技术栈逼迫让渡控制权**：从极度熟练的 TypeScript/Electron 切换到不熟悉的 Swift/AppKit，反而打破了开发者总想亲手掌控每一行代码的瓶颈。由于不懂，因而彻底放手让 AI 编写代码，自身退居为纯粹的需求定义与测试验收者，从而真正走入 AI 原生开发状态。

### 4. 重设计：不要让 AI 模仿人，以终为始重构架构
传统思维习惯于模拟人类既有流水线（如模拟字幕组的听写、打轴、翻译、校对步骤），导致在旧框架内修修补补、边际收益递减。AI 原生重设计遵循三项核心准则：
- **以终为始三连追问**：不再按人类习惯预先拆分字幕，而是利用 Whisper 词级时间戳（Word Timestamp）直接在完整句子级翻译对齐，再按时间戳自动重拆时间轴，消除繁重的人工校对；长文本前置提取术语表实现跨页注入；
- **让 Agent 操作其擅长的原生格式**：优先使用 HTML、Markdown 和纯文本等在大模型语料中海量出现的格式，而非自造奇特结构；
- **给设计规范不给固化模板**：遵循“苦涩的教训”，提供 Design System（颜色、间距、排版规则）让模型自主排版，而非塞入死板模版；
- **把 App 降级为 Agent 的插件**：用户交互入口已不可逆地从 App 界面迁移至 Agent 对话框。开发者甚至不再打开自研 App 的图形界面，而是由终端 Agent 调用命令行与 Skill 完成全流程闭环。详情页已退化为 Agent 的底层数据源。

### 5. 落地五关：研发瓶颈向代码两侧迁移
落地全流程依然遵循“可行性分析 → 设计文档 → 高保真原型 → 渐进实现 → 验收测试”，但执行主体剧烈转移：
- **文档升格为一等公民**：设计文档是人类确认方案与纠偏的最便宜载体，更是跨 Session 传递上下文的关键接力棒；
- **两侧瓶颈论**：Agent 可以在几小时内完成代码实现，软件工程瓶颈彻底转移至**代码左侧（需求定义、方案拍板）**与**代码右侧（功能、性能、安全验收）**；
- **验证题给 Agent，判断题留给人**：让 Agent 自行调用测试脚本验证代码功能，人类管理者则负责把关体验、方向与价值。

### 6. 个体共同进化：像训练大模型一样建立反馈循环
面对 AI 焦虑，个体成长的核心是**建立自收敛的自驱动循环（Loop Engineering）**：
- **双层反馈闭环**：以费曼学习法为内核，小循环做项目快速拿反馈，大循环做分享输出倒逼系统性输入；
- **敢于推翻旧权重**：大模型靠预训练、微调与对齐持续进化，人也必须敢于推翻过去的经验与认知壁垒；
- **刻意练习验收“品味”（Taste）**：代码细节可当做黑盒看待，不必纠结过度防御或格式；人类真正的护城河是对最终产物优劣的鉴赏力与边界判断力，必须通过海量的高质量输入与亲身动手实操来内化和提升。

## 关键引文

> "需求一直都在，是能力边界刚好扫过了它。同一个需求，模型没有检索能力时，它只是个普通提示词；能力到了，就能让所有人参与。需求一直都在，是能力边界刚好扫过了它。另一点是品味：人人都能用 AI 生成东西，想流行还是得有自己的品味，品味就是门槛。"

> "AI 产品的三条边界：能力线会动、成本线会动，价值线锚在人性上不动。"

> "在不熟悉的领域开始，反而更接近 AI 原生思维。用熟的语言有个坏处，你老想自己控制代码，一控制你就成了瓶颈，不放心让 AI 写。Swift 不熟，只能交给 AI，我只管验收，代码都不怎么看。正因为不熟才能放手，几天就做出能跑的 MVP。"

> "以终为始，不问‘原流程哪步还能优化’...从‘模仿人’到‘围绕 Agent 重设’...准则一：让 Agent 操作它最擅长的格式；准则二：给设计规范，不给模板；准则三：把 App 做成 Agent 的插件。"

> "瓶颈转移到代码两侧：Agent 几小时写完码，左边设计确认、右边测试部署还是人类速度，精力花在流程设计上比优化 Prompt 值得。"

> "这些年的经历用一个比喻说，就是像训练大模型一样训练自己...写出来收到反馈，反馈又帮我建立新的循环。模型也一样，预训练之后靠微调、对齐不断进化...很多时候要敢于推翻自己的旧权重。"
