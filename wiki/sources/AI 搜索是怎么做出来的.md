# AI 搜索是怎么做出来的

## 来源信息

- **标题**：AI 搜索是怎么做出来的
- **作者**：赛博禅心
- **发布日期**：2026-10-21
- **原始链接**：https://mp.weixin.qq.com/s/03UCiH5uhbpiIbzYa2i2FQ

## 核心要点

1. **搜索使用主体的范式迁移（从人类到 Agent）**：传统搜索由人类输入关键词并人工甄别十条链接；而在 Agent 时代，读取与决策主体转变为大语言模型与自主智能体。Agent 拆分复杂任务进行多轮迭代检索，带来了四大底层工程挑战：检索词由 Agent 拆解需深度理解意图、模型不辨真伪需前置过滤垃圾信息、模型预训练知识存在时间截断需动态补新、多轮级联调用要求极低延迟。
2. **检索词双向反馈机制与模型蒸馏**：传统意图理解靠人工规则，Agent 时代则转为搜索系统与智能体的双向信号互喂：
   - **搜索 → Agent**：输出每条检索结果的权威等级、发布时间与排序满意度，辅助 Agent 挑选置信引用；
   - **Agent → 搜索**：反向回传最终引用的条目、模型思考推理轨迹与答案打分（Answer Reward），作为排序模型的监督信号。
   元宝搜索采用 Label 模型大规模自动标注，训练大尺寸 Teacher 排序模型学习复杂偏好，再蒸馏为轻量 Student 模型上线运行；针对线上不满意 Case 自动挖掘并派发智能体标注，实现天级增量迭代（任务平均搜索次数从 8 次降至 5 次，翻页网页数从 20 降至 5）。
3. **信源真伪三级质量把关与 AIGC/GEO 攻防**：针对营销号水文和针对搜索引擎优化的 GEO（专门生成用于诱导 AI 引用）内容，系统在网页收录阶段即建立“站点、账号、页面”三级质量评分；部署专用识别模型对抗单篇低质 AIGC，按发布规律专项监控水文账号，同时对权威信源进行反向置顶与提权；对于反爬壁垒与高价值闭环站点（如携程等）则通过第三方商务与技术合作接入。
4. **垂直行业插件系统秒级补齐时效**：预训练模型无法感知秒级动态变化，常规网页爬虫小时级刷新仍无法满足股票、天气、航班等超高时效需求。元宝搜索构建了类似 Google OneBox / 百度阿拉丁的垂类插件系统，直连 13 个垂直行业 157 个头部信源（如腾讯自选股、飞常准、携程、京东等），在检索时直接调用合作方 API 封装为中文结构化卡片与网页结果合并返回，免除下游开发者逐一谈判授权的成本。
5. **极速低延迟链路：混合索引与 Gist Token 算力压缩**：Agent 多轮连搜对单次延迟极度敏感（单次慢 1 秒会导致整体体验崩塌）：
   - **索引层**：将倒排索引与向量索引融合为千亿级统一索引，召回率达 94% 以上，平均检索耗时仅 8ms；
   - **排序层（Gist Token）**：传统精排需将网页全文（几千 Token）与 Query 共同输入模型计算，开销巨大。元宝提出 **Gist Token** 机制，在索引建库期将网页预先压缩为 100 个 Gist Token 存入 [[concepts/概念_KV_Cache_键值缓存|KV Cache]]；在线查询时将 Gist Token 前置、检索词后置，精排计算量仅与检索词的十几个 Token 相关，命中缓存后单项节省约 30% 推理算力；
   - **推理框架**：自研跨卡型通用推理框架降低 90% 单位推理成本，将单次搜索延迟压缩至 300ms 以内，支持三轮连搜总耗时低于 1 秒。
6. **原子化检索工具与 Agent 多跳规划解耦**：搜索应定位为原子化的基础工具能力，单次请求只专注于精准检索一件事并返回条目摘录（支持通过 Cnt、站点限定、时间窗口与垂直领域过滤），严禁替代模型生成终极答案；多跳复杂问题（如“2026年诺奖最年轻得主任职大学的现任校长”）完全交由 Agent 通过多轮 `tools/call` 进行规划拆解（第 1 跳查得主、第 2 跳查任职大学、第 3 跳查校长），展现了“原子工具做快做准、上层 Agent 负责推理规划”的清晰架构分工。
7. **交付协议的三代演进（Plugin → FC → MCP/Skill）**：从 2023 年 ChatGPT Plugin（YAML 声明配置）演进至 Function Calling，再到当前的 [[concepts/概念_MCP协议|MCP（Model Context Protocol）]] 与 Skill 体系。MCP 作为面向模型的标准化“说明书”，通过 `initialize`、`tools/list` 与 `tools/call` 三步握手，将云端检索服务低成本注入 Codex 等智能体运行时。

## 关键引文

> “读结果的从人换成了 Agent，搜索面对的情况整个变了：检索词由 Agent 拆出来，搜索得听懂 Agent；读结果的模型不辨真假，真假只能由搜索来把关；模型的知识停在训练结束那天，新东西靠搜索补；Agent 一个任务要搜好几轮，每一轮都得快。”

> “建索引的时候，先把每个网页压成 100 个 Gist Token，这是人读不懂的向量，算好存进 KV Cache（模型算过的中间结果，存下来不用重算）；查询的时候，把这 100 个 token 放在前面、检索词放在后面，前面那段已经算好，只需算检索词那十几个 token。这样，排序的计算量只跟检索词长度有关。”

> “搜索是原子化的能力，一次请求只搜一件事；多跳规划，则是由 Agent 解决。原因也简单：第二跳该搜什么，要等第一跳的结果读完才知道。读结果、做判断的是 Agent，下一跳只能由它来定；搜索要做的，是把每一跳都搜准、搜快。”
