# 实体：方舟 AI 会场 Harness

## 简介

**方舟 AI 会场 Harness（Ark AI Venue Agent Harness）** 是由阿里巴巴淘天集团营销&交易技术团队（[[entities/实体_大淘宝技术|大淘宝技术]]）打造的生产级智能体外壳与运行环境。该系统突破了传统 AI 仅能生成不可上线、缺乏真实数据的静态 Demo 页面局限，构建出真正支持淘内商品供给圈选、真实货品运营且可直接向手淘端内与端外 C 端投放的工业级会场系统，达成“想法即生成，生成即可投放”的商业目标。

---

## 核心架构：三类环境的构建

方舟团队将 Agent Harness 定义为将“业务怎么做”转化为模型可理解、可操作、可检查的工作环境，重点构建了三类环境：

```
┌─────────────────────────────────────────────────────────────────┐
│                    方舟 AI 会场 Agent Harness                     │
├─────────────────┬───────────────────────┬───────────────────────┤
│  1. 会场域认知环境 │    2. 业务工作区环境    │    3. 自迭代与质检环境  │
│  - 30+ 视觉风格   │  - OSS 虚拟文件系统   │  - 确定性质检工具     │
│  - 数据插槽 Slot  │  - 按任务拆解委派     │  - 五层 LLM Trace     │
│  - Ark 生码协议   │  - P0-P3 上下文分层   │  - 真实业务闭环反哺   │
└─────────────────┴───────────────────────┴───────────────────────┘
```

1. **会场域认知环境（Domain Cognition）**：
   - 通过 Skill 体系向模型渐进式注入会场知识，包括内容认知（人群/场景挖掘）、视觉认知（30+ Design Skill 沉淀淘系设计规范）、供给认知（选品与投放映射）与生码协议（Ark 协议）；
   - **核心产物 `page.html` 的三维约束解耦**：
     - **视觉设计（软约束）**：守住排版与气质，允许模型发挥创造力；
     - **货品数据（认知约束）**：`data-ark-slot` 与 `data-ark-index` 写在 `<a>` 标签上，在 DOM 上解耦“视觉分组”与“供给分组”；
     - **生码（硬约束）**：严格定义 Section、卡片与字段边界，避免局部改动破坏布局前提。
2. **业务 Agent 工作区环境（Workspace & Context）**：
   - **OSS 虚拟文件系统**：通过 `ls/read/write/edit` 等工具操作工作材料，持久状态落盘 OSS，会话释放不丢产物，解除对单个进程生命周期的强依赖；
   - **文件收敛语义**：利用 `page-data.json` 收敛复杂的底层后端投放模型，降低模型每轮对话的认知负荷；
   - **SubAgent 任务拆解与委派**：主 Agent 持续负责用户交互与主决策，只在“输入输出说得清”（如内容挖掘）或“独立任务并行加速”（如分品类选品）时委派给 SubAgent，以“结论 + 执行记录文件路径”交接，避免信息损失；
   - **P0-P3 上下文分层与 Prompt Cache 权衡**：核心约束（P0）常驻，关键 Skill（P1）压缩后显式恢复，当前判断信息（P2）按需保留，过时工具输出（P3）在 5 分钟缓存冷却后通过“微压缩”清理，平衡上下文质量与 Prompt Cache 成本。
3. **自迭代与交付保障环境（Self-Iteration & Observability）**：
   - **确定性质检工具**：兼顾创造力与交付确定性，快速检测掉坑（区分缺格与不满）、旋转卡宽（变换前尺寸判定）、3×3 采样遮挡等；
   - **五层可观测体系（LLM Trace）**：下钻监控 Session、Turn、Request、Tool Steps 与 Provider 出口请求，沉淀用户需求打标体系，驱动 Agent 持续自迭代。
