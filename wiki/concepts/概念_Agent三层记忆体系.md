# 概念：Agent 三层记忆体系

**来源**：从代码生成到自主决策_Coding驱动的自我编程Agent

基于 Atkinson-Shiffrin Memory Model（1968）将记忆分为感知/短期/长期三层，在 Agent 工程侧实现持久化、结构化、可检索的记忆能力。

## 感知记忆（Sensory Memory）

- **维度**：标签页级，最短期
- **内容**：通过悬浮球捕捉当前页面信息、URL 等环境感知数据
- **失效条件**：页面任意操作（打开抽屉/弹窗）即失效
- **典型场景**：答疑时 Agent "看到"用户当前页面，提前预输入上下文减少用户描述成本

## 短期记忆（Short-term Memory）

- **维度**：Session 级，基于 ES 存储
- **格式**：统一 Segment 格式，三类消息：
  - **段落记忆消息**：存储 Thought/Command/Evaluation 等推理段落（含 execId + parentExecId 支持执行链追溯）
  - **实体记忆消息**：工具调用结果、用户关键信息、环境状态快照
  - **基础消息**：uuid/sessionId/tags/timestamp/sortValue
- **流程**：对话 → 产生 Segment → 存储 → 下轮检索 → 提供上下文

## 长期记忆（Long-term Memory）

- **知识点（短知识）**：一句话配置化知识指引，如"重新部署是流水线概念，重启是诺曼底运维概念"；比知识库文档更轻量，直接作为思考 Prompt 指引
- **历史会话摘要**：长期上下文连续性
- **用户画像**：角色定位、技能标签、工作习惯
- **代码执行经验**：人工审核 + 大模型投票机制录入经验图谱（规划中），成功经验供后续任务借鉴

## 与上下文窗口的关系

纯上下文拼接的局限：长度有固定 token 限制；无法有效组织检索历史；无法动态更新；计算成本高。三层记忆体系解决这些问题。

## 面试项目中的存储与维护方案

- DeepSeek 面试复盘中的项目将短期会话与工具结果保存在内存，把近期跨会话摘要放入 Redis，把长期偏好、事实和周期性任务放入向量库与 MySQL；当会话超过阈值时，以滚动窗口、摘要压缩和结构化抽取共同控制上下文。
- 快手面试复盘中的 miniclaude 采用当前会话上下文加向量检索长期记忆，并以重要性过滤器限制写入范围；其长期记忆仍是追加式写入，合并与摘要属于后续计划。
- 月之暗面面试复盘给出更细的上下文压缩策略：System Prompt 与最近 2-3 轮常驻，较早历史在软硬 Token 阈值下触发摘要；后续摘要以“旧摘要 + 新对话”增量重算，同时保留原始会话用于审计、摘要重建和长期检索。
- 高德面试复盘强调长期记忆检索后的融合治理：稳定偏好和历史事实不仅需要召回，还需处理更新、冲突、过期和隐私；两个时间相近但矛盾的事实不能只按时间覆盖，可引入置信度辅助判断。

- **DeepSeek AI Infra 实践**：强调“小模型筛选信息，大模型处理信息”的记忆治理理念。利用 7B 参数轻量模型生成长会话历史摘要与意图初筛，相比大模型直接总结可将推理成本压缩 90%、延迟降至 200ms。
- **美团 AI 全栈实践**：明确“保留决策信息，丢弃过程信息”的记忆压缩核心原则。当会话轮次超过 10 轮或 Token 占用达窗口容量 60% 时，触发 LLM 结构化事实提取（需求、决策、中间产物、待办事项），正文上下文仅保留紧凑摘要与最近 3 轮完整会话；正在进行的活跃任务上下文严格免除压缩。
