# 概念：LLM 模型路由

## 定义与机制

LLM 模型路由（Model Router）是部署在 LLM 网关（LLM Gateway）或智能体调度层的动态分发机制。其核心思想是根据用户 Prompt 的复杂度评估（如分为简单、标准、复杂、深度推理等层级），动态将请求分流至不同性价比的模型（例如将简单格式化请求路由给小型/廉价模型，将复杂多步任务分发给前沿大模型），以期在满足任务能力要求的同时大幅降低整体推理推理成本。

## 核心挑战与局限性

在实际高频复杂与 Agent 业务场景中，模型路由存在以下关键工程矛盾：

1. **Prompt 无法单向决定任务复杂度**：
   - Prompt 仅是任务的触发器（Trigger），真正决定上下文与计算复杂度的要素通常在后续的工具调用（Tool Calls）、网络搜索或代码执行反馈中逐步展开。
   - 静态/首轮文本评估容易产生误判（例如针对个人简单网页改代码 vs 针对大型复杂工程代码库测试，初始提示词结构可能高度一致）。

2. **路由机制与 Prefix Cache（前缀缓存）的收益冲突**：
   - 现代推理服务中，前缀缓存读取成本通常比无缓存输入便宜 75%–90%。System Prompt 和长多轮对话历史构成了主要的 token 开销。
   - 若引入跨模型路由，每次更换模型均会导致前缀缓存完全击穿失效；而若为了保留缓存添加路由粘性（Stickiness），路由策略本身则趋于静态化，失去动态分流意义。

3. **行为一致性与开发者调优受损**：
   - 不同模型在指令遵循、参数敏感度和输出风格上存在细微差异。动态漂移的模型选择削弱了确定性，且阻碍工程师深入掌握特定模型的行为边界。

4. **Agentic 系统的维护与不确定性成本**：
   - 在多智能体（Multi-Agent）与长程链路中，模型不确定性导致 Evals、System Prompts 调优和可观测性（Observability）维护成本激增，往往超过分流节省的微小推理开销。
