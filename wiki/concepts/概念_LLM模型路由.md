# 概念：LLM 模型路由

## 定义与机制

LLM 模型路由（Model Router）是部署在 LLM 网关（LLM Gateway）或智能体调度层的动态分发机制。其核心思想是根据用户 Prompt 的复杂度评估（如分为简单、标准、复杂、深度推理等层级），动态将请求分流至不同性价比的模型（例如将简单格式化请求路由给小型/廉价模型，将复杂多步任务分发给前沿大模型），以期在满足任务能力要求的同时大幅降低整体推理推理成本。

## 核心挑战与局限性

在实际高频复杂与 Agent 业务场景中，模型路由存在以下关键工程矛盾：

1. **Prompt 无法单向决定任务复杂度**：
   - Prompt 仅是任务的触发器（Trigger），真正决定上下文与计算复杂度的要素通常在后续的工具调用（Tool Calls）、网络搜索或代码执行反馈中逐步展开。
   - 静态/首轮文本评估容易产生误判（例如针对个人简单网页改代码 vs 针对大型复杂工程代码库测试，初始提示词结构可能高度一致）。

2. **路由机制与 Prefix Cache（前缀缓存）的收益冲突**：
   - 现代推理服务中，前缀缓存读取成本通常比无缓存输入便宜 75%–90%。System Prompt 和长多轮对话历史构成了主要的 token 开销。
   - 若引入跨模型路由，每次更换模型均会导致前缀缓存完全击穿失效；而若为了保留缓存添加路由粘性（Stickiness），路由策略本身则趋于静态化，失去动态分流意义。

3. **行为一致性与开发者调优受损**：
   - 不同模型在指令遵循、参数敏感度和输出风格上存在细微差异。动态漂移的模型选择削弱了确定性，且阻碍工程师深入掌握特定模型的行为边界。

4. **Agentic 系统的维护与不确定性成本**：
34	   - 在多智能体（Multi-Agent）与长程链路中，模型不确定性导致 Evals、System Prompts 调优和可观测性（Observability）维护成本激增，往往超过分流节省的微小推理开销。

36	## 前沿演进：HiRoute 每步动态评估与前缀缓存协同范式
37	
38	针对上述 Prompt 静态评估失真与前缀缓存失效两大痛点，开源本地 Agent 智能路由器 [[entities/实体_HiRoute|HiRoute]] 提出了兼顾任务动态性与缓存经济性的新一代工程解法：
39	
40	1. **场景粗筛与单步动态评估结合**：
41	   - 确立“复杂场景里有大量简单的活，简单场景里也会突发难题”的基本认知。
42	   - 场景层（如技术调研、工程代码、日常事务）仅负责圈定候选模型组（经济组 vs 主力组）与质量验收标准；具体到任务执行的每一步，才动态评估当前步骤的真实难度，实现“资料整理用经济模型、关键决策用主力模型”的精细分流，将整体任务成本降至纯强模型的 1/12。
43	2. **轮内锁定与缓存感知调度（Cache-Friendly Scheduling）**：
44	   - 打破“每步随意切换模型”的简单思维，确立严格的缓存纪律：**在一轮（Turn）任务连续调用中锁定模型不变**，仅在用户输入新消息、上下文被压缩或重建时触发重新选模。
45	   - 该策略使得单轮多达数十次的工具交互能够稳定维持在同一模型上，实现近 90% 的前缀缓存（Prefix Cache）命中率，避免频繁击穿缓存。
46	3. **System One 三问拆解与程序化阈值裁决**：
47	   - 针对大模型做复合路由判断时容易产生主观偏差（过分激进或过分保守）的缺陷，将决策拆解为三个正交的轻量问题：
48	     1. 上一步做得怎么样？（胜任度打分）
49	     2. 这一步有多难？（简单概率评估）
50	     3. 上一步的问题会不会带到这一步？（已知未决问题的延续性）
51	   - 坚持“让模型回答问题，让程序做决定”，由程序硬逻辑按设定的信任度阈值自动选组，消除了系统性主观偏差，选模准确率大幅提升至 88%–100%。
52	4. **观测驱动的自适应信任度放手**：
53	   - 以真实会话中用户的下一步反应（明确否定即不胜任证据）作为直接依据，建立非对称调整策略：多放手门槛（累积 30 步、覆盖 ≥3 会话、达标率 ≥85%）显著高于收回门槛（达标率 <70%）；任何阈值变动均通过离线历史回放验证。
54	
55	## 关联概念与实体
56	
57	- [[concepts/概念_KV_Cache_键值缓存]]：推理缓存核心机制，前缀缓存（Prefix Cache）对长上下文成本优化具有显著优势。
58	- [[concepts/概念_MoE_Router_专家路由门控网络]]：模型内部层级（Token 级）的稀疏专家路由，区别于网关层的整体请求路由。
59	- [[concepts/概念_RAG_Routing_检索智能路由]]：检索增强生成中针对不同知识库或查询类型的路由分发。
60	- [[concepts/概念_Decision_Model_专用判断模型]]：利用无生成的轻量判断模型进行快速确定性分支路由与工具前置拦截。
61	- [[concepts/概念_Super_Agent_超级智能体]]：常驻 Router 与独立 Worker 编排范式，可在底层复用模型路由计划。
62	- [[entities/实体_HiRoute]]：阿里云开源的本地 Agent 智能路由器，践行三问拆解与缓存友好调度。
63	- [[entities/实体_Jev]]：商业化判断接口在 Agent 路由中的工程实践。
