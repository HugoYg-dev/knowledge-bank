# 概念_Graph_RAG_知识图谱增强检索


## 定义

知识图谱 RAG（Knowledge Graph RAG）是将知识图谱作为 RAG 系统检索基础的方法，通过构建实体-关系图结构组织知识，实现多跳推理和跨文档关联检索，突破传统向量检索的扁平化局限。

## 核心要素

- 多层次知识库构建：从文档/Chunk到问题/社区/主题/类目的分层抽象
- 图检索：对关键节点进行向量和关键词检索，返回topN节点子图信息
- 与向量/文本检索结合：构成"混合语义+向量+图谱"三位一体混合检索架构
- 支持单跳和多跳链式检索

## 阿里实践（多层次知识库）

- 流程：Node（文档tree/工具/chunk）→ 问题（原子粒度）→ 社区（问题聚类）→ 主题（产品）→ 类目（产品线）
- 文档Graph：切分后挖掘核心问题/摘要/因素，构建Chunk图谱
- 工单Graph：根据工单间和内部chunk关系构图

## KG-RAG 成本与权衡（尹一峰 AICon）

- KG-RAG 适用于全局查询和聚焦总结，不适用于点对点问题
- 构建成本约为简单向量 RAG 的 1000 倍
- Lazy Graph RAG：语义搜索+KG 结合，索引成本降至上一代的 0.1%
- 设计原则：KG-RAG 用于全局/实体关系查询，Semantic Search 用于无结构数据快速检索

## SQL 关系型数据库替代静态全局图谱 (SAG)

针对传统 KG-RAG 离线构图需调用海量 LLM 导致构建成本暴增 1000 倍及增量维护难的问题，[[concepts/概念_SAG_动态超边结构化检索增强生成|SAG 架构]]提出了以关系型 SQL 替代图数据库的方案：
- **入库期解耦**：入库时仅抽取单篇自包含的事项卡片与关联实体，以标准行记录存入 SQL 数据库；
- **查询期动态组装**：通过 SQL 的 `JOIN` 操作在查询时就地组装局部关联图（动态超边），无需预先在全库范围计算静态知识图谱；
- **多跳确定性与低门槛**：在 MuSiQue 基准达到 80.04% Recall@5 的同时，将调优路径转化为透明的 SQL 日志排障，大幅消减了知识图谱在企业私有库落地的工程复杂度。

## 跨模态统一知识图谱（枫清科技）

- 将文档/图片/视频/关系型数据库的元素统一纳入图谱
- Graph RAG Light 提取文档实体关系（指定关注实体/关系降低成本）
- 图谱检索：向量匹配实体→N度扩展查询→提取含多模态信息子图

## 社区检测演进：Leiden 缺陷与 S2Dual 双重感知

在分层知识图谱与全局摘要构建中，社区检测（Community Detection）用于将密集的实体/关系划分为语义聚合的主题簇：
- **传统 Leiden 算法局限**：强制完全依据图拓扑连通性划分社区，对前端实体抽取与构图质量极度敏感；且全图遍历计算合并导致大规模图处理效率低下。
- **S2Dual 双重感知（优图提出）**：
  - **Structure（结构）感知**：通过稀疏邻接矩阵计算 Jaccard 相似度，量化锚节点与社区子图间的拓扑重合度与连接强度；
  - **Semantics（语义）感知**：编码锚节点特征与候选社区子图特征向量，捕捉文本语义重合度；
  - **工程效益**：突破单纯拓扑刚性连接限制，相比经典 Leiden 社区检测算法运行效率提升近 100%。

## 分层知识组织：知识树结构与四级粒度（优图实践）

针对传统图谱检索细粒度知识易脱靶、传统树结构（如 RAPTOR）缺乏细粒度关系推理的痛点，优图 GraphRAG 提出了融合图结构（细粒度推理）与树结构（层次化汇总）的**知识树结构（Knowledge Tree）**：
- **四级知识粒度树型异构图**：
  1. **属性节点**：承载实体的具体特征与键值参数；
  2. **实体与关系三元组**：连接核心语义单元，支撑多跳逻辑推理；
  3. **关键词节点**：抽取高频检索词，辅助倒排/稀疏索引快速命中；
  4. **社区节点**：结合 S2Dual 检测聚类社区，总结高层宏观摘要信息。
- **自适应 Schema 构图**：预置人物、事件、概念三大通用领域图 Schema；构图时大模型依据输入动态补充领域特化属性与关系，实现异构自适应融合。

## 两大类框架

1. **图结构方案**（GraphRAG、LightRAG）：知识粒度细化，但构图和检索质量/效率偏低，难以生产环境使用
2. **树结构方案**（RAPTOR、E2GraphRAG）：层次化迭代总结文本切片，但高度依赖大模型且无法挖掘细粒度知识关系
