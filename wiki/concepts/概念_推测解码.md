# 概念：推测解码（Speculative Decoding）

## 1. 核心定义与运行范式

**推测解码（Speculative Decoding）** 是一种旨在打破大语言模型（LLM）自回归解码访存带宽限制的高性能推理加速范式。其核心在于 **先推测后验证（Draft-then-Verify）** 的两阶段闭环：
1. **推测阶段（Drafting）**：借助低算力成本的草稿机制（如小模型、多预测头、隐层外推或浅层退出），在每个解码周期快速推测未来 $K$ 个候选 Token。
2. **验证阶段（Verification）**：目标大模型（Target Model）仅执行一次并行前向传播（Forward Pass），同时校验这 $K$ 个候选 Token 的自回归一致性。若前 $M$ 个通过、第 $M+1$ 个被拒绝，则输出前 $M$ 个 Token 以及目标模型即时生成的校正 Token，剩余草稿丢弃；若 $K$ 个全部通过，目标模型可在同次前向中直接产生第 $K+1$ 个有效 Token。

## 2. 核心数学性质：严格无损加速

推测解码的核心魅力在于**不损失模型输出分布与生成质量**：
- **贪婪解码（Greedy Decoding）**：只需校验推测 Token 与目标模型贪婪 Argmax 输出严格一致。
- **核采样 / 温度采样（Sampling）**：采用严格的拒绝与修正采样规则（如 Leviathan et al. 提出的推测采样分布修正公式），在数学上严格保证最终输出分布与直接使用目标大模型自回归采样完全相同。

## 3. 四大主流草稿变体范式

推测解码技术的演化主要集中于“如何以最低成本生成高质量草稿 Token”：

| 变体范式 | 代表框架 / 工作 | 草稿生成机制 | 目标模型依赖 | 显存与工程代价 | 典型加速比 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **独立双模型 (Two-Model)** | Speculative Sampling, vLLM Assisted Generation | 独立轻量小语言模型自回归生成 | **零改动**（目标模型完全冻结） | 需承载第二套模型参数与独立 KV Cache | 2x – 3x (T5-XXL) |
| **隐状态特征外推 (Feature-Level)** | [[实体_EAGLE]] | 轻量模块预测目标模型倒数第二层特征向量，前移输入消除多义性 | 训练专用的轻量前向特征外推网络 | 显存开销极低，需框架级专用服务集成 | 2.7x – 3.5x (LLaMA2-70B) |
| **多头并行与树状验证 (Multi-Head Tree)** | [[实体_Medusa]] (Medusa-1 / Medusa-2) | 顶层挂载多个 FFN Head 并行预测未来多步，使用树状注意力 (Tree Attention) 验证分支 | 训练外挂预测头（Medusa-1 仅训头；Medusa-2 联合微调） | 仅增加极少预测头权重，树宽决定瞬时验证显存 | 2.2x – 3.6x (Vicuna/LLaMA) |
| **浅层退出自推测 (Early-Exit)** | LayerSkip (Meta) | 共享模型架构，前几层 Transformer 输出草稿，深层校验 | **训练期前置干预**（Layer Dropout + 早退损失） | **零额外显存**，共享全部权重、激活值与 KV Cache | 1.8x – 2.16x (Code/Summary) |

## 4. 工程落地与选型决策维度

在工程部署落地推测解码时，加速比取决于以下核心制约要素：
1. **净加速度量标准**：实际收益取决于每次目标模型 Pass 净接受的 Token 数量（Accepted tokens per target pass）扣除草稿耗时与并行验证带来的额外计算开销。
2. **任务确定性与温度参数**：代码生成、数学推导、SQL 生成等低熵任务候选接受率极高，加速比最显著；而高温度的创意性文本接受率较低，加速效果收窄。
3. **并发批处理规模（Batching）**：推测解码在单请求/低并发场景下加速最显著（此时 GPU 处于访存带宽瓶颈）；在大 Batch 并发达到 GPU 算力饱和时，矩阵计算开销增大，推测解码的相对边际加速收益会明显降低。
4. **KV Cache 强协同**：所有推测变体均深度依赖高效的 KV Cache 机制（如 PagedAttention），以确保已接受的前缀 Token 和验证阶段的注意力状态无需反复重算。
