## 定义

**AI工程技术栈全景（AI Engineering Master Stack）** 是指导 AI 工程师在 2026 年构建、优化与运维生产级 AI 系统的分层架构体系。随着大语言模型技术从单纯的“API 调用”转向“系统级工程”，该全景图将复杂的 AI 系统解构为从底层模型数学表征到顶层生产安全运维的 **10 个关键层级**。这一体系反映了现代 AI 系统从“单点 Prompt 调试”向“整体 Harness（评测容器）与 Loop（控制循环）设计”的范式跃迁。

## 10层技术栈全景与核心组件

```mermaid
graph TD
    Layer10[⑩ LLMOps & Safety (生产运维与安全)] --> Layer09[⑨ Evaluation (闭环评估)]
    Layer09 --> Layer08[⑧ Inference Optimization (推理优化)]
    Layer08 --> Layer07[⑦ Fine-tuning (权重微调)]
    Layer07 --> Layer06[⑥ Context Engineering (上下文工程)]
    Layer06 --> Layer05[⑤ Agents (动作智能体)]
    Layer05 --> Layer04[④ Retrieval (检索/RAG)]
    Layer04 --> Layer03[③ Prompt Engineering (提示工程)]
    Layer03 --> Layer02[② Model Behavior (模型行为)]
    Layer02 --> Layer01[① Foundations (基础底座)]
```

### ① 基础底座 (Foundations)
- **定义**：决定模型如何从数学和结构上表征与处理输入信息。
- **核心组件**：Tokens (分词机制)、Embeddings (向量表示)、Transformer (注意力架构)、Attention (自注意力机制)、Context Window (物理上下文窗口限制)、Positional Encoding (位置编码，如 RoPE)、MoE (Mixture of Experts 混合专家架构)。

### ② 模型行为 (Model Behavior)
- **定义**：已经训练好的基础模型如何响应用户的输入和任务指令。
- **核心组件**：Pretraining (预训练策略)、Post-training (后训练对齐)、Sampling (采样解码)、Temperature (温度调节参数)、Reasoning Models (推理大模型，如 $o1$/$R1$ 类慢思考模型)、Multimodality (多模态感知)、Test-time Compute (测试时计算/推理期搜索)。

### ③ 提示词工程 (Prompt Engineering)
- **定义**：在不改变模型权重和外部数据的情况下，仅通过调整 prompt 的构造来塑造和约束模型的输出。
- **核心组件**：System Prompts (系统提示词级隔离)、Few-shot (少样本上下文学习)、CoT (Chain-of-Thought 思维链)、Structured Outputs (JSON/Schema 结构化约束输出)、Prompt Caching (提示词缓存)、Self-consistency (自洽性投票)、Meta-prompting (元提示词生成)。

### ④ 知识数据检索 (Retrieval/RAG)
- **定义**：向模型动态喂入其在训练阶段从未接触过的外部私域数据或实时数据。
- **核心组件**：Chunking (文本分块策略)、Vector Databases (向量数据库选型与检索)、Hybrid Search (稀疏/稠密混合检索)、Reranking (重排模型)、Retrieval Evaluation (检索相关性评估)、Query Rewriting (查询重写/扩展)、GraphRAG (知识图谱检索增强)。

### ⑤ 动作执行智能体 (Agents)
- **定义**：打破只答不做的黑盒，使大模型具备在复杂环境中自主决策、规划和执行外部操作的能力。
- **核心组件**：Function Calling (工具/函数调用)、ReAct (推理-行动循环)、Planning (多步规划与拆解)、Reflection (自我反思与纠错机制)、Multi-agent (多智能体协同流)、Computer Use (屏幕/OS 操控能力)、Human-in-the-loop (人机协同/半自动介入)。

### ⑥ 上下文工程 (Context Engineering)
- **定义**：控制和动态管理填充进模型有限上下文窗口中的内容，这是从静态提示向动态系统过渡的桥梁。
- **核心组件**：Context Management (上下文动态裁剪与填充)、Compaction (上下文信息压缩)、Memory (短期/中长期语义记忆)、MCP (Model Context Protocol 统一上下文协议)、Agent Harness (智能体运行容器)、Just-in-time Retrieval (即时检索注入)、Structured Note-taking (结构化草稿垫/知识沉淀)。

### ⑦ 权重微调 (Fine-tuning)
- **定义**：当提示词和上下文手段因容量限制、成本或格式对齐要求而无法满足业务时，通过训练直接修改模型权重来对齐特定任务。
- **核心组件**：SFT (监督微调)、LoRA/QLoRA (低秩适应微调)、RLHF (基于人类反馈的强化学习)、DPO (直接偏好优化)、Distillation (知识蒸馏)、GRPO (群体相对策略优化)、RLVR (可验证奖励强化学习)。

### ⑧ 推理伺服优化 (Inference Optimization)
- **定义**：优化模型在生产环境中的部署，使其更便宜、更快速地对外提供计算服务。
- **核心组件**：Quantization (模型量化，如 FP8/INT4)、KV Cache (键值缓存)、Batching (连续批处理 Continuous Batching)、Speculative Decoding (投机解码)、vLLM serving (高吞吐伺服框架)、FlashAttention & PagedAttention (内存/显存读写硬件优化)。

### ⑨ 闭环评估体系 (Evaluation)
- **定义**：系统性、定量化地度量和检验整个 AI 系统生成的正确性与稳定性。
- **核心组件**：Benchmarks (通用标准基准)、LLM-as-judge (大模型裁判校准)、Golden Datasets (黄金测试数据集建设)、Hallucination Detection (幻觉评测指标)、Regression Tests (回归测试集)、Trajectory Evaluation (智能体决策轨迹评估)、Red Teaming (红队安全攻防测试)。

### ⑩ 生产部署运维 (LLMOps & Safety)
- **定义**：确保 AI 应用系统在生产环境中的高可用性、可观测性、合规性与边界安全性。
- **核心组件**：Observability (运行链路 Trace 与日志分析)、Cost Tracking ( Token 与算力成本追踪)、Guardrails (输入/输出安全护栏过滤)、PII Redaction (敏感个人信息脱敏)、Feedback Loops (在线反馈收集与飞轮迭代)、Prompt Injection Defense (提示词注入/越狱防御)、Model Routing (动态模型智能路由)。

## 宏观视角趋势：从单点 Prompt 到 Harness & Loop 工程

1. **摆脱单点 Prompt 依赖**：过去 AI 开发者过度依赖编写完美的 Prompt。但在 2026 年，随着系统的复杂度提高，单个 Prompt 无法保证复杂长程任务的稳定性。
2. **Harness（容器/评测容器）的引入**：上下文工程（Context Engineering）和评估（Evaluation）要求为 Agent 提供一个标准容器。这个容器既为大模型在各执行环节提供即时的记忆、协议化的接口，又包含严格的多级沙箱和防御护栏（Safety Harness）。
3. **Loop（循环工程）的设计**：智能体不再是一个单向生成链，而是由 ReAct 逻辑、反射机制、多步规划等组成的自适应闭环（Loop）。工程师的精力从“润色字句”转移到“设计 Loop 的退出条件、纠错回滚机制、多样查询改写的路由路径”等系统架构逻辑上。
