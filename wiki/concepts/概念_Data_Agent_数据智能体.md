# 概念：Data Agent 数据智能体

## 定义

**Data Agent**（数据智能体 / 智能数据分析助手）是指将大语言模型（LLM）与企业数据资产、商业智能（BI）体系及查询引擎深度整合的自主智能体范式。它让业务人员能够通过自然语言交互完成数据查询、经营指标分析、多维归因与报告呈现。

与通用问答或编码智能体不同，Data Agent 的工业级落地对**业务口径的绝对精确性、行级数据安全权限与计算结果的不可妥协性**有着极高要求。

## 核心系统设计原则与权衡取舍

### 1. 系统边界定界（1.0 版本的取舍纪律）
在搭建 Data Agent 初始版本时，“明确系统不做什么”与“明确要做什么”同等重要：
- **聚焦高频核心闭环**：1.0 版本优先收敛于销售、客户、预算、同比等高频经营分析场景，直接复用既有 BI 系统的行级权限、预聚合计算与缓存加速；
- **主动做减法**：财务跨月结算明细、复杂自定义权限编排与多图联动大屏在初期应主动排除，防止因边界过宽导致评测失焦与系统稳定性崩溃；
- **放弃直接生成原生 SQL**：改为引导模型调用 BI 已经定义好的指标与元数据能力，口径交给语义层，权限由底层引擎强制执行。

### 2. 业务语义层（Semantic Layer）资产化工程
口径（如“销售额是否含税”、“退单口径”、“大客户门槛”）是数据系统的核心痛点。语义层不能是一次性 Prompt 拼装，必须作为长期演进的工程软件资产：
- **语义要素拆解**：通常将业务知识分解为术语映射、指标口径、业务对象与关系、数据资产字典、拒答话术与示例问答六大模块（或基于本体的强类型配置）；
- **代码化与 CI/CD 自动检查**：语义层资产统一采用 Git 版本化管理，配属多级 CI 门禁（检查 Schema 合法性、引用一致性、指标安全合规与行为回归测试），有清晰的 Owner、评审与秒级回滚机制；
- **冷启动与探索链路隔离**：针对尚未注册的新指标，允许在物理隔离的“探索链路”中试查；验证稳定且具备业务复用价值后，反推出指标公式经人工确认后正式入库，严禁探索结果自动污染生产语义层。

### 3. 翻译架构：放弃端到端直写 SQL，引入受约束中间态
成熟的企业级实践普遍摒弃了让模型从自然语言（NL）端到端直接生成物理 SQL 的做法：
- **直写 SQL 的层叠失败问题**：迫使模型在单次推理中同时猜测“业务含义、表结构、字段选取、JOIN 条件、过滤谓词、聚合算子”六件事，错误概率层层放大且无法归因；
- **分阶段受控翻译路径**：
  $$\text{自然语言 (NL)} \xrightarrow{\text{LLM 推理}} \text{受约束的业务语义稿 / 语义中间态 (IR)} \xrightarrow{\text{确定性翻译器}} \text{物理 SQL / BI API} \xrightarrow{\text{校验与沙箱}} \text{执行器}$$
  模型仅负责将自然语言转化为强类型的业务语义表达（严禁直接出现物理表名/字段），实际物理表选择与关联计算完全由确定性翻译模块接管。

### 4. 工具设计最小化与正交性
- **出口集中化**：取数入口应高度收敛（如单一取数出口工具，其余分别负责主题定位、指标定义、权限预检与图表渲染），避免工具职责重叠引发模型选择漂移；
- **结构化错误返回**：工具返回必须具备结构化异常码（如“累计字段误用 SUM”、“行数超限”、“字段不存在”、“权限不足”），驱动模型做精准的分支决策（收紧条件、重新检索或转为异步报告），严禁仅返回笼统的“查询失败”。

### 5. 提示词引导 vs 确定性引擎硬拦截（两道防线）
- **职责划分**：提示词负责引导模型的意图理解与倾向；而不可逾越的业务红线（如累计字段不可累加、同比区间对齐、行数保护上限、只读限制）必须交由查询引擎做确定性硬校验；
- **短时令牌（Token）绑定**：使用与查询指纹绑定的短时令牌防范流程绕过，确保执行前必须经过语义翻译与校验环节。

### 6. 拒答治理与全链路分层归因评测
- **拒答是合法生产终态**：明确维护拒答话术库，对越权、域外、缺失或超时查询果断拒答。说清“为什么答不了”远优于硬凑虚假数字；
- **全链路可归因评测**：评测体系需覆盖单点单元测试、口径一致性校验、黄金数据集回归与安全压测，核心目标在于归因错误发生的具体层级（意图理解、语义定义缺失、权限异常还是工具失误）。
