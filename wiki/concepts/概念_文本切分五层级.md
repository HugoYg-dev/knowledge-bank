# 概念_文本切分五层级


## 定义

将 RAG 文本切分划分为五个逐级递进的层级框架，从简单到复杂：

1. **Level 1: Character Splitting** — 简单的固定字符长度切分
2. **Level 2: Recursive Character Text Splitting** — 基于特定字符分隔符进行递归切分和合并
3. **Level 3: Document Specific Splitting** — 针对 Markdown, JSON 等特定文档格式的物理结构切分
4. **Level 4: Semantic Splitting** — 基于句子相似度和向量距离的语义相似度切分
5. **Level 5: LLM-based / Agentic Splitting** — 基于大语言模型（或 Agent）语义判断的自适应智能切分

## 5种策略结构化汇总

| 切分级别与策略 | 核心机制 | 优点 | 缺点 / 挑战 | 适用场景 |
| :--- | :--- | :--- | :--- | :--- |
| **Level 1: 字符切分 (Fixed-size)** | 按固定字符/Token数切分，保留一定重叠 (Overlap) | 极简、高效，便于批处理 | 易打断句子、破坏语义连贯性 | 基础测试、无明显语义结构的规整文本 |
| **Level 2: 递归字符切分** | 逐级（段、句、词）使用分隔符尝试切分，超出限制则递归 | 较好保留自然语言结构，默认首选 | 规则仍然固定，不随文本内容语义变化 | 大多数通用文本文档 |
| **Level 3: 文档结构切分** | 识别标题、表格、JSON等物理标记进行分块 | 保持物理与逻辑排版完整性，利于检索回溯 | 极度依赖排版规范，块大小差异可能过大 | API 响应 (JSON)、开发文档 (Markdown)、代码 |
| **Level 4: 语义切分 (Semantic)** | 计算句子向量相似度，在语义变化过大处进行断句 | 保持语义完整与流动，检索精度高 | 依赖相似度阈值设定，跨文档泛化难 | 语义转换频繁、学术论文、复合分析报告 |
| **Level 5: LLM-based / Agentic** | 借助 LLM / Agent 动态判断语义边界并生成文本块 | 语义准确度最高，能深度理解语境 | 计算开销高，速度慢，受上下文长度限制 | 极高检索精度要求、短篇复杂文档 |

## Level 5: LLM-based Chunking 详解

- **原理**：通过特定的 Prompt 指引大模型，将输入的整篇长文解析成语义上高度自洽、独立且完整的文本块。
- **优缺点分析**：
  - **优点**：智能度极高，能够真正理解上下文含义、修辞及复杂转折，而非依赖字符或相似度阈值等简单启发式规则。
  - **缺点**：这是所有切分技术中计算开销最大、响应最慢的方法；此外，调用 LLM API 会产生费用，且受到模型输入上下文窗口的制约。

## 进阶切分范式扩展（Advanced Chunking）

除了经典五层级外，面向生产级复杂问答演化出以下突破“分块大小与语义上下文矛盾”的进阶切分范式：
1. **Late Chunking（延迟切分）**：先使用长上下文 Embedding 模型对整篇完整文档进行全局编码，然后再按物理边界截断 chunk。每个 chunk 的向量天然融合了整篇文档的全局语境，彻底解决孤立分块缺乏上下文前置信息的问题；
2. **Small-to-Big（以小博大检索）**：在索引与检索阶段使用小粒度 chunk（如单句或短段落）实现高精确度命中，但在生成阶段自动向外展开到包含父节点、相邻段落或所在完整章节，兼顾检索命中精度与生成上下文完整性；
3. **Intent-Driven Dynamic Chunking（意图驱动动态切分）**：超越纯粹基于文档自身格式或统计相似度的切分规则，结合预测的用户潜在信息需求动态划分边界，使 chunk 结构直接贴合下游查询意图。
