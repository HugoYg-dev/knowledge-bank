# 概念_机器学习模型生产环境测试

在模型离线评估（使用验证集和测试集）通过后，直接全量替换生产环境模型存在极高风险。因此，ML 团队通常会使用生产环境测试策略，通过真实的线上数据评估候选模型（Candidate Model）相较于基线/遗留模型（Legacy Model）的表现。

## 核心策略

### 1. A/B 测试 (A/B Testing)
- **定义**：将线上流量以非均匀或均匀的比例随机分配给遗留模型和候选模型。
- **机制**：通常限制候选模型的曝光流量（如只分流 5% 或 10%），以将潜在的线上异常风险降到最低。
- **局限**：对分配到流量的用户具有全局随机性，可能影响到随机选中的所有用户。

### 2. 金丝雀测试 (Canary Testing)
- **定义**：将新模型首先暴露给一小部分特定子集的用户（例如按地域、用户 ID 尾数等维度），并在确认运行稳定后，逐步推广至所有用户。
- **机制**：与 A/B 测试的随机分流不同，金丝雀测试针对的是特定的用户组，且重点在于评估系统稳定性与错误率的平滑演进。

### 3. 交叉测试 (Interleaved Testing)
- **定义**：将遗留模型和候选模型的预测结果混合在一起返回给用户。
- **机制**：在同一个请求中，将两个模型的输出进行交叉混合展现。例如，推荐系统可以将遗留模型推荐的前 3 个商品与新模型推荐的前 3 个商品交替展示，通过用户点击反馈来直接对比两者的优劣。
- **特点**：能够在更少的样本和时间下，提供比传统 A/B 测试更敏感的对比指标。

### 4. 影子测试 (Shadow Testing / Dark Launch)
- **定义**：将线上请求同时复制并发送给候选模型，但候选模型的预测结果不直接返回给用户，只作记录和监控。
- **机制**：候选模型部署在与生产环境相同的流量管线中进行测试，确保环境真实性；输出会被记录，用于后续与遗留模型的 benchmark 评估。
- **优势**：由于不影响用户端体验，因此具有零风险特征。

### 5. 多臂强盗部署 (Multi-armed Bandits Deployments, MAB)
- **定义**：一种自适应的分流机制，利用动态探索（Exploration）与利用（Exploitation）平衡来分配流量。
- **机制**：基于强化学习算法（如 Thompson Sampling 或 UCB），根据模型的实时表现自动增加优秀模型的流量比例，减少较差模型的流量。相较于传统 A/B 测试，它能最大限度地减少测试期间因模型表现不佳导致的业务损失。
