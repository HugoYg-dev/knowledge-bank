# 概念_文档结构切分


## 定义

文本切分五层级中的 Level 3。让切分策略适配不同的数据格式（JSON、Markdown、代码、PDF 等），依据文档自身固有的层级和逻辑结构（如标题、段落、嵌套字典）进行切分，保持其物理与逻辑排版的完整性。

## 特点

- **优点**：能最大化维持文档原本的结构和上下文语义完整，有利于在检索中根据父子关系回溯上级内容。
- **局限**：非常依赖文档排版与结构的规范性。另外，因为以物理结构而非长度进行划分，生成的 Chunk 大小可能相差悬殊，甚至会超出嵌入模型的 Token 上限。此时可尝试将其与递归字符切分结合。

## JSON 切分

- 遍历 JSON 数据深度，构建更小的 JSON 块
- 尽量保持嵌套 JSON 对象完整，在需要时拆分以控制块大小
- 大字符串值不会被自动分割（需要时组合递归文本分割器）
- **列表问题**：大列表会被完整保留导致片段超长
- **解决方案**：`convert_lists=True` 将列表转换为 `{index: item}` 字典形式

## 实现

- LangChain：`RecursiveJsonSplitter(max_chunk_size, min_chunk_size)`
  - `split_json(json_data, convert_lists=True/False)`
- LLama-Index：`JSONNodeParser()` + `get_nodes_from_documents([Document(text=json.dumps(data))])`

## Markdown 与 PDF

- Markdown 按标题层级、段落与代码块切分，并把完整标题路径写入元数据。
- PDF 先以版面分析区分标题、正文、表格和图片，再合并跨页段落后切分。
- 除块本身外保留父子关系和相邻块信息，以便检索后补足局部上下文。

## 多格式文档中间表示（IR）解析范式

针对 Office（Word/PPT/Excel）、PDF、EPUB 及 RTF 等多格式混杂场景，[[entities/实体_Firecrawl|Firecrawl]] 开源的 [[entities/实体_anydoc|anydoc]] 提出了一种解耦的两阶段结构化解析范式：
1. **字节特征格式识别**：绕过扩展名伪装，直接通过头部字节特征识别真实文件类型；
2. **中间稿（Intermediate Representation）抽取**：统一将文档解析为结构化中间稿，完整保留层级标题、表格合并单元格、列表、代码块、脚注及幻灯片备注；
3. **标准化 Markdown 渲染**：将中间稿输出为清晰紧凑的 Markdown，使下游切分器能够无损继承原始文档的结构边界。纯 Rust 实现下单文件解析耗时低至 4.4ms，为 RAG 知识库与 Agent 数据供给提供了高效底座。
