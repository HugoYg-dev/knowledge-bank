# 概念：LLM 应用评估体系

## 定义

LLM 应用评估体系是指在大模型应用开发全生命周期中，对 Prompt/RAG/Agent 输出质量进行系统性、可重复评估的方法论与工具集合。

## 核心原则

### 1. 断言式单元测试

基于生产输入/输出样本，至少设置 3 个评测指标：
- 少于 3 个指标表明任务未充分定义或过于开放
- 工作流任何更改（提示词/RAG/模型）都应触发测试

### 2. LLM 裁判（LLM-as-Judge）

用最强模型对其他模型输出打分——**定性比较有用，具体幅度无参考价值**。

最佳实践：
- 成对比较优于量表打分（选择更好的一个，结果更稳定）
- 每对交换顺序各做一次（消除位置偏差）
- 允许宣布平局
- 搭配 CoT（解释决定后再给偏好），可让小模型达到大模型效果
- 注意 LLM 偏向较长回答

### 3. "实习生测试"

> "如果将提示词作为任务交给相关专业的普通大学生，他们能成功吗？"

判断逻辑：
- 大学生做不到 → 需要提供更丰富上下文
- 无法通过改进上下文解决 → 任务对当代 LLM 太难
- 大学生能做到但很慢 → 尝试降低复杂性/拆解任务
- 大学生能快速完成但 LLM 不行 → 深入研究失败模式

### 4. 古德哈特定律警惕

"当一项指标成为目标时，它就不再是一项好指标。"

典型案例：大海捞针测试被快速刷榜后失效。更好的指标是复杂实际任务（如会议记录总结特定要素），超越死记硬背，考察解析/识别/归纳综合能力。

### 5. 指标过强化的副作用

- 强调事实一致性 → 摘要变得不具体（为避免与事实不符）
- 强调写作风格 → 更多花哨话术（可能与事实不符）

### 6. Agent 完整交互轨迹评估（Full Trajectory Evaluation）

对于具有复杂规划与多轮交互能力的智能体（如 [[实体_Claude_Code]]、Dash Chat）：
- **不能只看最终文本**：必须评估其意图理解、上下文选择、检索搜寻、工具调用及归纳推理等中间决策。
- **人工标注与评判器校准**：收集带追踪日志（Traces）的数据，人工给出细粒度评分、失败编码（Failure Codes）和推理理由（Reasoning Notes）。
- **优化评判器**：使用 [[实体_DSPy]] 优化 LLM-as-a-Judge 的提示词，使其打分逻辑高度对准人类专家认知。
- **评估驱动提示词优化**：将对准的评判器嵌入反事实回放（Counterfactual Replay）与Agent系统自动优化闭环中，通过 GEPA/MIPROv2 算法迭代提升 Agent 质量与降低成本。

#### 轨迹样本的轻量化过滤：基于轻量行为信号的采样策略

DigitalOcean 提出了在生产环境中对海量 Agent 交互轨迹进行低成本筛选的策略，解决了高昂的人工标注成本与低效随机采样之间的矛盾。该策略通过定义确定性的、无需大模型（No-LLM）参与的轻量化行为信号，从 8 万条原始轨迹中精准筛选出 100 条高价值的 review 样本，实现了 82% 的信息价值率（相比之下，随机采样仅 54%）。

轻量行为信号可分为以下三类：
1. **交互信号**：通过对对话文本进行归一化短语匹配及语义相似度检测，自动识别用户纠错或重述（提示对齐存在偏差）、智能体自身重复（停滞 Stagnation）、用户直接放弃（流失 disengagement）以及用户表示解决（满意 satisfaction）。
2. **执行信号**：直接从 Agent 执行日志中提取，识别无效的 Tool 调用（对完成任务没有贡献）以及输入参数轻微漂移的死循环调用。
3. **环境信号**：提取底座系统环境错误（如 Rate limit、OOM、API 超时等）。这些信号对于系统诊断有用，但不能反映 Agent 的决策质量，故不计入决策采样。

**业务收益与隐性缺陷发现**：
该策略不仅在整体上将高价值样本率提升至 82%，更关键的是，在 Agent 最终结果判定正确的“成功轨迹”中，该策略仍能捞出 66.7%（而随机采样仅 41.3%）具有隐性缺陷的样本——例如执行效率低下、冗余步骤、违规调用 Policy 等。这使团队能低成本发现那些“结果正确但过程低效”的隐性缺陷，为 Agent 的链路优化与策略重构提供了极佳的标注池。

## 11 种核心评估指标与方法 (11 LLM Evaluation Metrics)

大模型应用评估的指标和方法可划分为以下 11 种核心类型：

1. **BLEU**
   - **定义**：将模型输出与参考答案切分为 n-gram，计算输出中被参考答案覆盖的比例，并通过长度惩罚（Brevity Penalty）抑制由于遗漏关键信息导致的虚高分数。
   - **使用局限**：对“语义相同但用词不同”的干净改写（Paraphrase）无法识别，会判定为零分。
   - **最佳实践**：仅适用于翻译或严格受限的生成任务（其中参考答案是唯一的标准答案）。建议计算语料库级（Corpus-level）得分，并提供多个参考答案。

2. **ROUGE**
   - **定义**：与 BLEU 相反，主要度量召回率（Recall），即参考答案中有多少 token 包含在模型输出中。ROUGE-L 使用最长公共子序列（LCS），比 ROUGE-2 具有更好的词序容忍度。
   - **使用局限**：单纯的召回率会鼓励模型生成冗长垃圾信息，带来偏见。
   - **最佳实践**：适用于摘要和提取任务（漏掉信息代价较大）。必须与精确度指标（Precision-side Metric）并用，避免模型过度冗长。

3. **BERTScore**
   - **定义**：利用预训练语言模型提取输出和参考答案的 Token 嵌入（Embedding），计算两组 Token 之间的相似度，并汇报精确率、召回率和 F1 值。
   - **使用局限**：得分绝对值通常落在一个极窄的高区间内，数值本身不具备直观的准确率含义。
   - **最佳实践**：能有效解决 BLEU/ROUGE 的改写识别问题。仅用于系统间的相对横向对比；需匹配特定领域和语言的 Embedding 模型，并可采用基线重标定（Rescaling the baseline）来提升区分度。

4. **G-Eval**
   - **定义**：通过给判别模型（如 GPT-4）输入任务描述和评分标准，让其自动生成思维链（CoT）评估步骤，并结合 Token 生成概率对打分结果进行加权。
   - **使用局限**：打分容易产生波动，极度依赖提示词设计。
   - **最佳实践**：适用于没有标准答案的主观准则评估（如语气、指令遵循、领域正确性等）。编写具体的核对清单（Checklist）而非形容词性描述可提升一致性；运行判别器时应采用低温度（Temperature），并在大规模应用前通过少量人类标注数据进行校准。

5. **LLM-as-Judge**
   - **定义**：利用强大的大模型作为裁判，根据给定的准则（Rubric）在两个或多个输出之间进行成对比较（Pairwise），选出表现更好的一个。
   - **使用局限**：容易受到位置偏差（裁判偏好靠前或靠后的答案）以及长度偏见（裁判偏好更长的答案）的影响。
   - **最佳实践**：最适合在绝对分值漂移的情况下比较两个模型、提示词或检索配置。最佳实践要求打分时必须随机化输出顺序，并对文本长度进行控制。

6. **Human Eval**
   - **定义**：由专业的人类标注员针对不同维度对输出进行评分，其聚合的评分结果作为评估自动化指标的“黄金法则”。
   - **使用局限**：成本高昂、耗时长、难以大规模自动化。
   - **最佳实践**：主要用于两处——一是构建校准 LLM 裁判的基准数据集，二是上线前的终极安全/质量关卡。必须在标注前明确评判规则并测量标注者间一致性（Inter-annotator agreement）。

7. **LLM Juries (大模型陪审团)**
   - **定义**：让多个不同的模型作为裁判独立评分，然后通过平均或投票机制汇总为最终结论。
   - **使用局限**：如果使用同一种模型家族的多个实例，无法消除特有的系统性偏见，反而会使成本成倍增加。
   - **最佳实践**：用于消除单一裁判的偏见（例如偏好自身家族模型生成的答案）。应选用多个**不同模型家族**组合，多个低成本小模型的陪审团性能通常优于单一昂贵大模型裁判。

8. **DAG (有向无环图/决策树评估)**
   - **定义**：通过预设的决策树，使输出通过一系列确定性节点，每个节点评估一个极窄的问题，并根据回答路由至下一个节点，最终到达的叶子节点即为最终得分。
   - **使用局限**：仅限于能够被硬性逻辑或结构化条件约束的规则，无法评估复杂的开放式语义。
   - **最佳实践**：非常适用于格式依从性检查、必含章节、或免责声明等硬性规范。应将廉价的确定性检测节点放置在决策树根部，以便失败输出能够尽早退出，节约模型调用成本。

9. **Trajectory Accuracy (轨迹准确率)**
   - **定义**：捕获智能体（Agent）运行过程中的完整思维步骤、工具调用和观察记录，并将该执行路径与预期轨迹进行对比打分。
   - **使用局限**：需要健全的分布式链路追踪（Tracing）系统作为前提。
   - **最佳实践**：由于 Agent 有可能通过歪门邪道或冗余的工具调用侥幸获得正确答案，必须将“路径轨迹”与“最终结果”分开独立评分，防止侥幸正确的破碎路径被掩盖。

10. **Multi-turn Eval (多轮评估)**
    - **定义**：以整个多轮对话为评测单元，系统性地评估对话在长跨度下的角色设定依从性、上下文关联记忆、以及前后一致性。
    - **使用局限**：对长上下文处理和评估成本高。
    - **最佳实践**：单轮或二轮评估无法暴露大模型在多轮交互后显现的约束丢失（例如第 5 轮遗忘了第 1 轮设定的规则）。应使用真实的生产对话日志，而非合成的简短对话进行评估。

11. **Safety Eval (安全评估)**
    - **定义**：并发运行偏见、毒性、PII（个人隐私泄露）等分类器，对模型输出中的违规内容进行实时阻断或打标。
    - **使用局限**：不提供质量打分，仅进行拦截和分类判定。
12. **Deep Research 报告量化评估信号 (Deep Research Evaluation Signals)**
    - **背景**：针对长篇研究报告、行业调研等非 Coding 场景，缺乏类似单元测试的确定性可验证标准，传统产品易陷入“片面求长”的虚假详实陷阱。
    - **双维解构**：从「包含哪些信息」（事实覆盖度）与「信息如何组织」（理解成本）两个维度切入，提炼客观量化信号。
    - **核心信号**：
      - **信息量（Fact Density）**：采用 Agent as a Judge 抽取报告中客观事实点/数据点总数并横向归一化，剔除主观评价性修饰词。
      - **隐喻率（Metaphor Rate）**：统计每百句中隐喻表达出现次数，强制要求输出直白字面替换进行反向校验，量化模型文风生硬度与信息映射损耗（$y=f(x)$ 导致信息单向丢失）。
    - **中间过程记录与 Harness 闭环**：中间研究笔记的记录格式直接决定最终报告质量（Bullet points 优于长文本摘要总结），通过评估反馈反向指导 Agent 系统提示词与 Harness 行为。

## 幻觉处理

幻觉率降至 2% 以下极难，即使在摘要等简单任务中。双层应对：
- **生成上游**：提示工程（CoT 让模型先推理）
- **生成下游**：事实不一致护栏（检测/过滤/重生成）

同时需持续记录输入输出以供调试监控。
