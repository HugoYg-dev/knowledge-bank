# 概念：PagedAttention（分页注意力）

## 1. 定义与设计背景

**PagedAttention（分页注意力）** 是由 UC Berkeley 团队在开源大模型推理引擎 [[entities/实体_vLLM|vLLM]] 中提出的革命性显存管理机制。其核心思想是将经典操作系统中的**虚拟内存分页（Virtual Memory Paging）**机制迁移至大语言模型的 [[concepts/概念_KV_Cache_键值缓存|KV Cache]] 管理中。

在传统的 LLM 推理系统中，由于自回归解码（Autoregressive Decoding）过程每次只能生成一个 token，且用户最终的输出长度事先未知，系统只能采取**静态预分配连续显存**的保守策略：
1. **内部碎片（预留过多）**：若按最大上下文长度（如 2048 或 4096 token）为每个请求预先分配连续显存，若请求仅生成数十或数百个 token 就提前结束，未使用的显存将被持续霸占；
2. **外部碎片（空间难以分配）**：即便全局空闲显存总量充足，但由于物理显存被零碎占用，往往无法找到一段满足长上下文请求所需的连续物理地址区间，新请求只能被迫排队等待。

传统推理系统中高达 **60%～80% 的显存浪费**都源于这类预留与碎片。PagedAttention 正是为了彻底打破“显存必须物理连续存储”的假设而诞生的。

## 2. 核心架构与寻址机制

PagedAttention 模仿操作系统的页表机制，建立了一套逻辑空间与物理空间的解耦映射：

```
逻辑视角 (连续虚拟块):
[ 逻辑块 0: Token 1~4 ] -> [ 逻辑块 1: Token 5~8 ] -> [ 逻辑块 2: Token 9~... ]
          |                           |                           |
          v (块表 Block Table 映射)   v                           v
物理显存池 (离散物理块):
[ 物理块 7 (显存位置 A) ]   [ 物理块 2 (显存位置 B) ]   [ 物理块 19 (显存位置 C) ]
```

### 2.1 块划分与块表（Block Table）
- **固定大小的块（Block）**：系统将请求的 KV Cache 划分为固定容量的逻辑块，每个块容纳固定数量的 token（常见为 4 个或 16 个 token 的 Key/Value 向量）；
- **离散物理存储**：在 GPU 物理显存中，各个块不需要连续排列，而是可以离散分散在显存池的任意位置；
- **块表映射与按需扩展**：系统为每个并发请求维护一张块表（Block Table），记录逻辑块到物理块的映射关系。
  - **初次分配**：请求进入时，根据 Prompt 长度分配若干物理块；
  - **单步写入**：逐 token 生成时，新生成的 KV 写入当前块的空位；
  - **动态领块**：当当前块完全写满时，系统动态向全局显存池申领下一个物理块，并在块表中追加映射。

### 2.2 碎片消除收益
通过分块分页设计，一个请求在生命周期内**最多只会在最后一个未写满的物理块中浪费少量位置**，显存浪费率从传统预分配的 60%～80% **骤降至 4% 以下**。

## 3. 基于 PagedAttention 的高级能力延伸

### 3.1 前缀缓存复用（Prefix Caching）
PagedAttention 的固定块划分天然使得跨请求缓存共享变得极为高效：
- **块级指纹计算**：系统为每一个已写满 token 的物理块计算确定性哈希指纹（涵盖该块内容及其所有前置上下文）；
- **多会话复用**：当多个用户请求共享相同的系统提示词（System Prompt，例如 `“你是一个专业设计师...”`）或 Few-shot 样本时，新请求可直接通过块表复用已计算好的物理块，免去重复计算与存储开销；
- **提示词工程启示**：在业务 Prompt 编排中，**固定前缀置前、动态参数置后**，能最大化块指纹命中率。

### 3.2 显存池集中调度与抢占（Preemption）
- **统一显存池**：所有物理块在服务启动时被初始化为全局显存池，由 Engine Core 集中管理分配与回收，消除频繁调用 CUDA `cudaMalloc` / `cudaFree` 的高昂系统调用开销；
- **抢占容错**：当突发高并发导致显存池耗尽时，调度器可直接根据块表将部分低优先级请求的物理块挂起（换出至 CPU 或丢弃重算），保障核心请求平稳生成。

## 4. 选型权衡与工业影响

| 维度 | 传统连续分配 | PagedAttention 分页管理 |
| :--- | :--- | :--- |
| **显存浪费率** | 60% ～ 80%（内外碎片严重） | < 4%（仅余最后一个未满块） |
| **并发承载力** | 较低（受限于连续显存碎片） | 大幅提升（显存池几乎 100% 被有效并发填充） |
| **系统吞吐量** | 基础吞吐 | 提升 2x ～ 4x 以上 |
| **算子复杂度** | 标准自注意力算子即可执行 | 必须定制开发非连续内存访问的高性能 CUDA Kernel |
| **生态代表** | 原生 PyTorch、早期 Hugging Face | [[entities/实体_vLLM|vLLM]]、SGLang、TensorRT-LLM |
