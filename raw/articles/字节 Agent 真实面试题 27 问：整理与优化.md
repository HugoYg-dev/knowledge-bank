## 一、工具与 MCP 适配层

### Q1. 为什么要把工具封装进 MCP 适配层，再交给 ReAct Agent 调用？

| 原因 | 说明 |
| --- | --- |
| 核心解耦 | Agent 专攻推理，不面对复杂协议 |
| 统一治理 | 处理校验、权限、超时、审计 |
| 灵活扩展 | 从硬编码变为可插拔组件 |

通俗案例：  
你请了一个翻译，不需要他同时懂签证、订票、酒店协议。  
你给他一个统一接口：把需求告诉前台，前台去对接各方。  
翻译只管翻译，前台只管协调。  
MCP 适配层就是那个前台。

---

### Q21. 如何保证 Agent 调用工具的可靠性，防止跑偏？

三道防线：

**第一防线：语法与类型**

- • 强制开启 JSON Mode。
- • 加持严格 JSON Schema 与 Pydantic 强类型约束。
- • 参数非法直接拦在本地。

**第二防线：安全风控环**

- • 对“转账、删库、重置、发邮件”等高风险副作用操作，必须挂载 HITL（Human In The Loop）人工确认挂起。

**第三防线：自愈闭环**

- • 捕获 API 报错或类型异常后，将原生 Error 堆栈甩回大模型，让其改写参数重试，通常 2-3 次收敛。

通俗案例：  
寄快递。

- • 第一关：地址格式不对，系统直接不让下单。
- • 第二关：寄的是贵重物品，必须本人签字确认。
- • 第三关：快递员第一次没找到地址，打电话问清楚再送一次。

## 二、写入安全与权限隔离

### Q2. 做增删改场景，如何避免模型把错误直接写库？

| 策略 | 做法 |
| --- | --- |
| 意图分离 | 模型仅输出结构化参数 |
| 后端网关 | 经过权限校验与事务控制 |
| 人工介入 | 高风险操作强制二次确认 |

通俗案例：  
银行柜员。

- • 柜员只负责填单子，不直接改账本。
- • 账本由后台系统审核后统一更新。
- • 大额转账必须主管授权。

### Q25. 企业知识库权限隔离怎么做？

**错误做法：在提示词里拦截**

试图在 Prompt 里要求大模型“不要泄露总裁和秘书的事情”，是徒劳且危险的。

- • 提示词软隔离 = 裸奔。
- • 大模型抗注入攻击能力差，极易通过角色扮演绕过 Prompt 安全限制。

**正确做法：纯物理级硬隔离**

1. 1\. **落库时打 ACL 标签**  
	每个切片的 Embedding 外带业务系统 ACL 元数据，比如部门 ID、密级。
2. 2\. **检索前注入身份向量**  
	在 Search 之前，向数据库强插当前 Token 拥有者的身份标签条件。  
	让越权文档连进上下文窗口的资格都没有。

通俗案例：  
公司档案室。

- • 错误做法：门上贴纸条“请勿偷看总裁文件”。
- • 正确做法：每个档案柜有门禁，你的工牌只能开你权限内的柜子。

## 三、Agent 工作模式与架构

### Q3. Agent 常见的工作模式有哪些？

| 模式 | 特点 | 适用场景 |
| --- | --- | --- |
| ReAct | 边推理边调工具 | 开发任务 |
| Plan-Execute | 先规划再执行 | 复杂任务 |
| Workflow | 固定流程 | 线上核心业务 |

通俗案例：

- • ReAct：边走边问路。
- • Plan-Execute：先看地图再出发。
- • Workflow：坐地铁，固定线路，每站必停。

### Q12. Agent 基本架构跟 LLMChain 到底差在哪里？

| 维度 | LLMChain | Agent 智能体 |
| --- | --- | --- |
| 本质 | 预定义的线性工作流 | 规划、记忆、工具使用和推理循环 |
| 执行路径 | 硬编码固化，静态流水线 | 根据核心目标自主决定 |
| 调整能力 | 缺乏动态规划与自适应调整 | 能根据环境反馈动态调整 |

通俗案例：

- • LLMChain：火车轨道，只能沿固定路线跑。
- • Agent：出租车司机，根据路况和目的地自己选路。

### Q17. 工作流和自主智能体，到底该如何选择？

| 类型 | 特点 | 适用场景 |
| --- | --- | --- |
| 静态工作流（求稳） | 基于 DAG 或状态机写死，高度可靠可预期 | 报销单审计、规范化客服 |
| 自主智能体（求变） | 放权让算力做黑盒调度、自我判断调用路径 | 无边界探索性研究、开放式代码生成 |

核心心法：

> 越靠近公司核心利润 / 风控业务，越要限制其自主行动空间；  
> 越偏向创意与研发环节，越要放权。

通俗案例：  
财务报销必须走固定流程，不能自由发挥。  
广告创意可以放权，让 Agent 自己探索。

### Q22. LangGraph 的节点和边与传统工作流有什么区别？

| 维度 | 传统工作流 | LangGraph |
| --- | --- | --- |
| 边 | 画死了就是画死了，A 到 B 再到 C 永不可变 | 动态条件边，下一节点由 LLM 推演动态路由 |
| 容错 | 中间一个环节微小失误，整个作业崩溃退出 | 支持闭环，节点可不断与环境互动纠错直到成功 |
| 灵活性 | 静态枯燥 | 循环重试基石 |

通俗案例：

- • 传统工作流：火车，脱轨就完蛋。
- • LangGraph：越野车，遇到坑可以绕、可以倒、可以换路。

## 四、RAG 基础与优化

### Q4. 怎么理解 RAG？

| 维度 | 说明 |
| --- | --- |
| 本质 | 检索增强生成，解决知识滞后 |
| 收益 | 私有知识、长尾知识效果显著 |
| 边界 | 逻辑推理任务上 RAG 需谨慎 |

通俗案例：  
开卷考试。

- • RAG 让你带参考书进考场。
- • 但如果你不会推理，翻书也做不出奥数题。

---

### Q5. RAG 的基础链路怎么讲？

| 环节 | 关键点 |
| --- | --- |
| 数据清洗 | 拉开差距的不是数据库，而是数据清洗 |
| 切分策略 | 元数据利用与语义切分 |
| 重排机制 | 召回后的二次排序是核心 |

通俗案例：  
做菜。

- • 食材不洗干净，后面怎么炒都不好吃。
- • 切法不对，口感全毁。
- • 最后摆盘顺序，决定先吃哪道。

---

### Q24. RAG 系统中，检索到互相矛盾的片段如何处理？

| 策略 | 做法 |
| --- | --- |
| 元数据高低权倾斜 | 按时间新鲜度、权威等级施加权重影响召回名次 |
| 智能体法庭辩论 | 同权重矛盾时，启动不同 Prompt 立场的并发 Agent 提取双方冲突断言 |
| 防背锅原则 | 向终端用户回复必须透出底层分歧溯源链接卡片，由用户做最终裁决 |

通俗案例：  
两个医生说不一样。

- • 先看谁职称高、谁更近期发表意见。
- • 职称一样，让他们各自陈述理由。
- • 最后把两种意见都告诉病人，让病人自己决定。

---

### Q26. 知识库更新频繁，RAG 系统怎么跟上节奏？

| 策略 | 做法 |
| --- | --- |
| 动态路由躲避延时 | 高度时效性追问，前置分类 Agent 放弃检索静态向量，直接调网络搜索 API |
| Kafka 增量灌水管道 | 业务数据表 Row 级变动，CDC 监控丢入 Kafka，触发流式后台异步重新做块 Embedding |
| 高频失效的 TTL | 头部热点查询答案部署短倒计时缓存失效，源文件指纹变异立刻清理脏热数据 |

通俗案例：  
新闻编辑部。

- • 突发新闻，直接上直播，不翻旧报纸。
- • 日常更新，后台慢慢排版入库。
- • 头条缓存五分钟一换，避免播旧闻。

### Q27. 生成答案时要插入图片、要处理大表格，怎么搞？

| 问题 | 方案 |
| --- | --- |
| 插入图片 | 图像占位符戏法：让模型抛特殊 Mark 语法块，由工程前端层拦截，替换为产品级 React 图片组件 |
| 大表格 | 拒绝全表暴力喂饭：先传表头字段目录和摘要，Agent 若发觉有用，产出精准 Pandas/SQL 请求，只裁剪微量子表格交给大模型深读 |

通俗案例：

- • 图片：不直接塞图片，先放一个“此处应有图”的占位符，前端再替换。
- • 表格：不把几万行 Excel 全丢给 LLM，先看目录，再要哪几行给哪几行。

## 五、记忆机制

### Q6. 长期记忆和短期记忆如何区分？

| 类型 | 内容 | 存储 |
| --- | --- | --- |
| 短期记忆 | 会话上下文，保证对话连贯 | Redis / 内存 |
| 长期记忆 | 持久化用户偏好与任务目标 | 向量库 / 关系型 DB |

通俗案例：

- • 短期记忆：会议白板，开完会擦掉。
- • 长期记忆：个人档案，跨会留存。

### Q7. 短期记忆压缩什么时候触发？

| 触发条件 | 说明 |
| --- | --- |
| Token 负载 | 接近上下文限制上限 |
| 会话深度 | 对话轮次过长影响性能 |
| 阶段迁移 | 任务进入全新业务节点 |

通俗案例：  
背包快满了，就该整理。  
聊太久了，就该总结。  
换项目了，旧笔记可以收起来。

### Q8. 智能压缩和机械压缩有什么区别？

| 类型 | 做法 | 特点 |
| --- | --- | --- |
| 机械压缩 | 截断或保留最近 N 轮 | 快、准 |
| 智能压缩 | AI 生成摘要，保留约束与计划 | 慢、但保留关键信息 |
| 混合模式 | 近处原文，远处智能摘要 | 兼顾成本与效果 |

通俗案例：  
会议记录。

- • 机械：只留最近十分钟录音。
- • 智能：让助理写会议纪要。
- • 混合：最近十分钟留录音，前面的看纪要。

### Q13. ReAct 模式里，记忆机制到底如何落地？

| 类型 | 落地方式 |
| --- | --- |
| 短期记忆 | 驻留当前上下文窗口，实时保存对话历史与工具调用结果状态 |
| 长期记忆 | 以向量数据库形式存在，跨会话前先根据 Embedding 检索历史经验和人物偏好 |
| 务实方案 | 增加“摘要层级”，通过递归压缩旧对话，避免海量 Token 推高成本、稀释注意力 |

通俗案例：  
看病。

- • 短期：这次问诊的对话。
- • 长期：你的既往病史档案。
- • 务实：太久远的病历，写成摘要，不全文塞给医生。

### Q20. 多轮对话，状态爆炸和上下文溢出如何处理？

| 策略 | 做法 |
| --- | --- |
| 结构化脱水 | 在流程图中严密定义状态变量骨架，内存只存纯逻辑变量，拒绝存储无关痛痒的散漫回话 |

| 强制头部冷凝 | 久远历史喂给小模型榨出高度精炼摘要，永远作为提示词前置背景强塞给主 LLM |

通俗案例：  
整理行李箱。

- • 只带必需品，不带有感情但没用的东西。
- • 护照、机票必须带。
- • 旧衣服压缩成真空袋，省空间。

## 六、多智能体协作

### Q9. 多智能体场景里，模型选型怎么平衡成本和效果？

| 角色 | 模型选择 |
| --- | --- |
| 小模型 | 处理分类、摘要、格式校验 |
| 强模型 | 负责规划、推理、最终审计 |
| 性价比 | 执行层根据复杂度动态选型 |

通俗案例：  
医院。

- • 分诊台护士做初步分类。
- • 主任医师做复杂诊断。
- • 不是每个人都要挂专家号。

### Q14. 单 Agent 也能干活，为什么还要上多 Agent？

| 维度 | 说明 |
| --- | --- |
| 单点痛点 | 单个 Agent 处理跨领域极度复杂长任务时，背负过多工具与指令，极易推理链断裂 |
| 多核价值 | 每个 Agent 只盯自己那一亩三分地，提高容错率与领域专业度 |

通俗案例：  
一个人又当厨师又当服务员又当收银，忙不过来。  
分工后：厨师只管炒菜，服务员只管上菜，收银只管结账。

### Q15. 多 Agent 常见的协作模式有哪些？

| 模式 | 特点 | 适用场景 |
| --- | --- | --- |
| 中心化策略 | 主控 Agent 拆解任务，派发给 Worker 子 Agent，执行后中心汇总 | 高可控场景 |
| 流水线串联 | 上一个 Agent 的输出严丝合缝作为下一个的输入 | 构建 > 审查 > 修复工程流 |
| 民主协作探讨 | 多个 Agent 根据各自系统身份与设定进行圆桌讨论后得出共识 | 线上策略分析偶尔使用 |

通俗案例：

- • 中心化：包工头派活。
- • 流水线：工厂装配线。
- • 民主协作：专家会诊。

### Q16. 多智能体系统怎么防无限循环和通信爆炸？

| 防线 | 做法 |
| --- | --- |
| 最大迭代熔断（物理级） | 硬编码 Max Iterations 重试次数阈值，触发后强制抛出中止异常 |
| 状态机边界控制（逻辑级） | 为每次流转定义清晰的工作完成判断函数 Exit Condition，不达标不换阶段 |
| 通信摘要瘦身（内容级） | Agent 网络互发消息强制经过 Token 级别语义总结，屏蔽闲聊，传输纯净 Payload |

通俗案例：  
开会。

- • 物理级：会议最多开两小时，到点散会。
- • 逻辑级：议题没结论，不许进入下一项。
- • 内容级：发言必须写在一张卡片上，不许闲聊。

### Q18. 编排者-执行者模式怎么拆分任务才不翻车？

| 问题 | 做法 |
| --- | --- |
| 核心挑战：拆分粒度 | 切太碎，通信开销爆炸；切太粗，Worker 理解吃力易诱发幻觉 |
| 实战经验：一任务一验收 | 下发给子节点的任务，必附带唯一 Done 验收指标，完成边界明确 |
| 一致性验证收口 | 主 Agent 汇总前，先调用校验模块自运行一次审判，不过关则打回重做 |

通俗案例：  
装修。

- • 任务太碎：每颗钉子都要汇报，累死。
- • 任务太粗：让一个工人搞定全屋水电，他搞不定。
- • 正确：一个房间一个验收标准，做完检查，不合格重做。

## 七、错误处理与性能评估

### Q10. Agent 有没有熔断机制？

| 机制 | 做法 |
| --- | --- |
| 失败阈值 | 连续调用失败即停止重试 |
| 步数限制 | 防止无限死循环调用 |
| 错误降级 | 权限错误终止，服务异常切换 |

通俗案例：  
打电话。

- • 打三次不接，别再打了。
- • 打了半小时还在拨号，挂掉。
- • 对方关机，换微信联系。

### Q11. 模型服务卡死，后端怎么兜底？

| 策略 | 做法 |
| --- | --- |
| 网关治理 | 超时、限流、多商户切换 |
| 业务降级 | Agent 模式退化为普通问答 |
| 模式互备 | 主模型挂掉切备用模型 |

通俗案例：  
餐厅。

- • 主厨忙不过来，先上凉菜。
- • 主厨病了，副厨顶上。
- • 实在不行，告诉客人今天只供应套餐。

### Q19. Agent 怎么自我纠错？反思模式怎么落？

| 策略 | 做法 |
| --- | --- |
| 告别自欺欺人 | 让单一 Agent 自问自答等于“学生改自己的卷子”，成功率极低 |
| 引入独立 Critic 节点 | 设定纯挑刺不干本职活的法官 Agent，只做一件事：用最严苛 Prompt 校验输出是否破限 |
| 长期记忆错题本 | 对以往翻车日志提取轨迹池，下次执行同类任务时打卡对齐，实现绕坑而行 |

通俗案例：  
考试。

- • 自己改自己的卷子，看不出错。
- • 找个专门挑错的老师来改。
- • 把以前错题整理成错题本，下次考前翻一翻。

### Q23. 如何量化 Agent 的性能？

| 层级 | 指标 | 说明 |
| --- | --- | --- |
| 底线指标 | 任务最终成功率 | 基本盘，代表智能化是否及格 |
| 效能指标 | 平均推理步数 | 步数越少 = Token 消耗越低 = 响应越快 |
| 精密指标 | 工具调用精确度 | 选对枪配好子弹 |
| 推荐方法 | 线上影子双流测试 | 拿同基线请求同时跑新旧 Agent，对齐输出差异验证 |

通俗案例：  
考核外卖员。

- • 底线：有没有送到。
- • 效能：送了几单、花了多久。
- • 精密：有没有送错、拿错。
- • 影子测试：让新老外卖员跑同一单，对比结果。

## 八、总结：2026 最深考点四大方向

| 方向 | 核心问题 |
| --- | --- |
| 上下文工程 | 记忆分级、压缩、状态管理、上下文溢出 |
| 工具可靠性 | MCP 适配、参数校验、权限、熔断、自愈 |
| 多 Agent 协作 | 选型、拆分粒度、协作模式、防循环、防通信爆炸 |
| RAG 权限隔离 | 物理级 ACL、检索前注入身份、矛盾处理、增量更新 |

一句话记忆：

```
上下文要分级，工具要可控；
多 Agent 要分工，RAG 要硬隔离。
拆得清、控得住、协得好、隔得开。
```

## 九、面试速答口诀

| 问题 | 一句话答案 |
| --- | --- |
| 为什么封装 MCP | 解耦推理与协议，统一治理，可插拔扩展 |
| 增删改怎么防错 | 模型只出参数，网关校验事务，高风险人工确认 |
| Agent 工作模式 | ReAct、Plan-Execute、Workflow |
| RAG 本质 | 检索增强生成，解决知识滞后 |
| RAG 链路关键 | 数据清洗、语义切分、重排 |
| 长短期记忆区别 | 短期会话上下文，长期持久化偏好 |
| 压缩触发时机 | Token 满、轮次多、阶段迁移 |
| 智能 vs 机械压缩 | 机械截断快，智能摘要准，混合最优 |
| 多 Agent 选型 | 小模型分类摘要，强模型规划审计 |
| 熔断机制 | 失败阈值、步数限制、错误降级 |
| 模型卡死兜底 | 网关治理、业务降级、模式互备 |
| Agent vs LLMChain | 静态流水线 vs 动态推理循环 |
| ReAct 记忆落地 | 短期上下文，长期向量库，摘要层级压缩 |
| 为什么上多 Agent | 单 Agent 跨领域易推理链断裂，多 Agent 提高容错与专业度 |
| 多 Agent 协作模式 | 中心化、流水线、民主协作 |
| 防无限循环 | 最大迭代、状态机边界、通信摘要瘦身 |
| 工作流 vs 自主智能体 | 核心业务求稳，创意研发求变 |
| 编排者-执行者拆分 | 一任务一验收，一致性验证收口 |
| 自我纠错 | 独立 Critic 节点 + 长期记忆错题本 |
| 状态爆炸处理 | 结构化脱水、优先级裁剪、强制头部冷凝 |
| 工具可靠性 | JSON Schema、HITL、自愈闭环 |
| LangGraph vs 传统工作流 | 动态条件边 vs 静态画死 |
| 性能量化 | 成功率、平均步数、工具精确度、影子测试 |
| RAG 矛盾处理 | 元数据权重、法庭辩论、溯源给用户 |
| 权限隔离 | 物理级 ACL，检索前注入身份，绝不靠 Prompt |
| 知识库更新 | 动态路由、Kafka 增量、TTL 失效 |
| 图片大表格 | 占位符戏法，表头先行，按需裁剪 |
