# 给语言模型装一个动态分类头

做智能体的时候，到处都要做选择。挑工具、给工单分流、判断一段内容是否合规，这些事过去一律交给通用大模型，构造一段提示词，让几十亿参数的自回归模型逐字吐出一段 JSON。慢的时候两秒，快的时候也要几百毫秒，偶尔还会编造工具名，或者 JSON 截断在半路上。

很多人尝试给大模型套上 JSON 约束或结构化输出。这确实管住了格式，输出不会再缺括号，但没解决速度问题。底层依然在自回归循环里转圈，GPU 照样要机械地逐字吐出大括号、字段名、冒号和引号。如果业务要的是高频判定，带着语法约束生成终归也是生成，自回归解码带来的显存带宽开销一点没少，几十毫秒的硬指标依然过不去。

2026 年 9 月 Jev 走红。这个模型完全不生成文字，给它一段状态描述和预设选项，只返回各选项的概率和置信度，延迟七八十毫秒，官方公布的输入单价是每百万 token 0.042 美元，约为前沿大模型的四百分之一。第一次看到确实觉得新鲜。

开源社区的反应非常快。上线不到三天，就有人用几行代码在 Qwen 4B 上跑通了单步打分的推理路径。顺着这些开源项目看下去，从本地读 logits 的 SemIf，到把 0.8B 模型塞进浏览器的 jev-fire，再到 Convai 开源的 4.21 亿参数的 Laya，对照着 Archer Hume 的黑盒评测，技术路径其实很清楚，也很值得拆开来讲。

## 一、直接从因果语言模型里抽取分值

最快的复现方式甚至不需要训练新权重。

现代因果语言模型的输出层本身就是一个巨型线性分类器。如果模型的隐藏维度是一千，词表大小十五万，最后一层的权重就是一千乘十五万的矩阵。平时生成文本，模型是在这十五万个候选词里逐个算概率挑下一个词。如果任务只是判断一封工单该转给财务、技术还是销售，候选缩到了三个，两边差了五万倍。

做法很直接。提示词送进去，跑一次前向传播，取出序列末尾的隐藏状态，送入输出层拿到十五万维的分值向量。然后丢掉十四万九千九百九十七个无关词，只抽出三个候选对应的分值，在这个小集合内部重新做 Softmax。从概率论看，这一步算的是条件概率，在已知输出必然落在这三个词的前提下，各选项分到多少。

开源项目 SemIf 用完全冻结的 Qwen 4B 跑这套逻辑，零训练零微调，在 Jev 官方 102 个判断任务上达到了 84.5% 的准确率。Jev 自己是 88.3%，差距不到四个百分点。另一个叫 jev-fire 的项目更激进，把仅 0.8B 参数的 Qwen 模型塞进浏览器用 WebGPU 跑，单步决策 71 毫秒，比 Jev 云端 API 的 178 毫秒中位延迟还快，API 费用直接省掉了。

工程落地上，这套逻辑也不需要自己手动侵入 PyTorch 源码去截取张量。现代推理引擎（例如 SGLang 的打分端点）已经把这层操作收录为原生接口。客户端只要传过去提示词和候选词对应的标记编号，服务端在前向传播结束的瞬间，直接在显存内完成切片和局部归一化。

```python
import requests

# 工业推理引擎将此抽象为单次打分请求，无需进入解码循环
response = requests.post("http://localhost:30000/v1/score", json={
    "query": prompt,
    "label_token_ids": [token_A, token_B, token_C],
    "apply_softmax": True
})
probabilities = response.json()["scores"]
```

拿到的直接是离散概率分布，整个过程完全跳过了生成循环。几行代码就能跑通这件事，说明从前向传播中提取指定标记的分值并做局部归一化，在算法层面确实没什么秘密。

## 二、分词器里的陷阱与闭集防线

跑通和工程可靠之间，隔着一个很容易踩到的细节。

现代语言模型用 BPE 分词。同一个单词前面带不带空格，编码出来的标记编号完全不同。比如 billing 单独出现时编号可能是一万四，前面加个空格变成两万八。提示词里候选标签紧跟上文，自然带着前缀空格。代码在查找词表索引时漏掉这个空格，拿到的就是另一个语境下的分值，概率分布会严重跑偏。

更棘手的问题出在长单词上。有些词没办法用单个词元覆盖，比如 technical 会被分词器切成 tech 和 nical 两段。

取第一段 tech，它的分值其实覆盖了所有以 tech 开头的单词，包括 technology、technician、tech lead，概率虚高。取最后一段 nical，由于前文没有出现 tech 这个前缀，模型在当前位置预测一个孤零零的 nical 的概率接近零，这个选项直接被误杀。而且由于长词需要拆成多个词元，多步条件概率连续相乘还会引入严重的长度惩罚偏差。

社区在工程上有两套应对办法。

最稳妥也最省事的做法，是在提示词里把选项编成代号，写清楚 A 代表财务，B 代表技术，C 代表销售。在绝大多数主流分词器里，单字母永远只占一个词元，绝不会被切碎。模型读完上下文和选项说明，注意力机制已经在末尾吸收了完整语义，这时让它单选一个字母，分词环节不会有任何损耗。

如果业务非要直接对长短不一的自然语言短语打分，就不能只看末尾那一个词元。这时只能沿着词组逐字算条件概率，把各步的对数似然累加起来，再除以带惩罚因子的长度系数 $|W|^\alpha$，抵消长词天然概率偏低的衰减。

绕过分词陷阱后，还要防备数学上的假象。

局部 Softmax 算的是条件概率，计算建立在一个强假设上，即真实答案必然落在给定的候选项内。如果系统遭遇一封黑客注入邮件，或者完全无关的异常内容，由于分母被死死限制在三个选项之间，错误选项依然会被强行分走全部的概率，甚至可能由其中某项高分胜出。

闭集打分必须给自己留一条退路。最直接的办法，是在候选项里永远提供一个兜底标记，比如 D 对应其他或转人工，给预料之外的输入留出兜底空间。更底层的防线，则要靠模型在全局表征层面识别出输入已经脱离了预设范围。

## 三、因果解码器做分类的天花板

分词和闭集问题有办法应付，但因果解码器自身的结构缺陷绕不过去。

因果掩码规定信息只能单向流动。前面的字看不见后面给出了哪些选项，上下文和候选项之间的语义交互从一开始就不完整。

硬件效率上同样不经济。自回归文本生成是典型的显存带宽受限任务，每吐出一个字，GPU 都要把几十亿参数重新读一遍，算力单元大部分时间在干等显存搬运。单步打分虽然利用密集矩阵乘法把算力打满了，但为了拿到三个选项的相对高低，GPU 依然要先算出十五万维的浮点数，再通过索引把绝大部分扔掉。自回归结构为了支持生成还要维护 KV Cache，显存和调度器的开销一直压着。

如果目标是高频调用、每次只要几个浮点数的判断节点，值得换个做法。

## 四、双向编码器加动态掩码

开源的 Laya 模型在这件事上给出了一套完整方案。它选用 3.95 亿参数的 ModernBERT-large 做主干（算上顶层决策头与行动网络，全模型总计约 4.21 亿参数），二十八层 Transformer，隐藏维度一千零二十四，全双向注意力。

全双向意味着输入序列中每一个字、每一个选项描述，在每一层都能互相看见。状态文本和候选选项之间的语义匹配是完全对称的，没有因果掩码带来的信息遮挡。硬件上，整个推理就是一次密集矩阵乘法，能把 GPU 的 Tensor Core 打满，实测耗时三十三到三十八毫秒。

光换主干还差一步。过去 BERT 做分类，句首标记后面接一个固定大小的全连接层，类别数量在写代码时就定死了。实际业务中选项随时在变，分类头必须支持运行时动态绑定。

### 把选项写进输入序列

Laya 的做法是在组装提示词时，给每个选项描述的末尾插入一个 [MASK] 标记。假设一封退款邮件需要判断转给哪个部门，拼出来的输入大致是邮件正文在前，后面依次排列各候选部门的描述，每段描述末尾跟着一个 [MASK]。

这些 [MASK] 在全双向注意力下同时结合邮件正文和所属部门的说明，并在同一层里兼顾其他选项。不管传入两个选项还是二十个，只需要在提示词里多插几个 [MASK]，网络结构一点不用动。

### 顶层决策变换层

主干编码完成后，Laya 额外加了两层 Transformer。这两层专门用来让各选项的 [MASK] 向量互相计算注意力，拉开彼此的区分度，建立排他的竞争关系。

### 用 gather 算子精准抽取

文本长短不一，每个 [MASK] 在序列中的物理位置动态变化。一封短邮件的 [MASK] 可能在第十五位，一封长邮件的可能跑到第三百位。程序在分词阶段记下每个 [MASK] 落在第几位，然后调用 PyTorch 的 gather 算子，直接按索引从几百行的大矩阵中取出目标行，拼成规整张量。这步只做显存地址重排，耗时在微秒量级。

### 动态缩放校准与三种原语统一

抽出来的向量经全连接网络映射为标量分值后，不能直接用固定参数做 Softmax。选项数量一变，分母上的累加项就变了。两个选项时瞎蒙的概率是百分之五十，二十个选项时只有百分之五。同样输出百分之七十的概率，前者没多大把握，后者说明模型非常确定。

为了让输出的概率具备真实的统计意义，Laya 针对任务类型和选项数量预先拟合了缩放参数，在 Softmax 前对分值做调节。这样无论当前有几个选项，算出来的置信度都保持一致的衡量基准。

统一了打分标尺之后，智能体里五花八门的选择题，基本都能收敛到三种形态里。

一种是工单路由或意图选择这类的无序单选，直接吐出各选项的离散概率与置信度。一种是有序评级，比如评估故障严重度是零到三级，除了给出各档位概率，还能用期望公式 $\mathbb{E}[S] = \sum i \cdot p_i$ 算出一个连续平滑的分值，比如 1.84 级，把程度上的渐变留下来。最后一种是非题，专门对付钓鱼拦截或越狱检测，直接输出一个校准过的风险概率。

### 用校准决策强化学习让概率不撒谎

温度缩放解决了选项数量变化带来的分母漂移，但下游程序凭什么把模型吐出的概率数字当真？

用传统交叉熵做分类训练，损失函数只有当正确选项的分值趋近无穷大时才能最小化，模型天然被逼向过度自信。用标准强化学习也好不了多少，命中得一分、落空得零分的二元奖励同样把最高概率往一点零猛推，其余选项的分值被压到接近零，破坏了整体概率分布的校准度。

Jev 和 Laya 走的路线叫 RLCD，校准决策强化学习。核心思想是把奖励函数换成严格适当评分规则。在决策理论里，一个评分规则被称为严格适当，当且仅当报告的概率分布恰好等于真实分布时，期望得分能够唯一地达到最大值。只有如实报告自身把握，模型才能拿到最高奖励，任何虚报都会被扣分。

Laya 在训练中组合了三种评分。对数评分重罚对正确类别给低概率的情况，球面评分提供有界的平滑信号防止梯度爆炸，排序概率评分则专门针对有序量表教会模型理解等级之间的远近。三者叠加，从不同角度同时约束模型输出诚实的概率。

温度缩放是训练后的后处理方式，通过统一调节参数来拉平概率，无法针对具体样本改变把握的高低。RLCD 则在训练阶段直接将校准作为优化目标，改变权重本身。

## 五、系统该不该自己拿主意

拿到分类概率之后，很多自动化系统写一条规则，最高概率超过某个阈值就放行。真实业务里，单一阈值很容易翻车。

两种典型情形。模型面对两个选项，给出百分之五十一和百分之四十九的概率，最高分勉强过半，但两个选项咬得死紧，误判风险极大。另一种，十个选项里第一名拿到百分之六十，剩下九个都在百分之四上下，虽然绝对值只有六成，但它比第二名高出五十多个百分点，模型其实很笃定。

只看最高概率，分不出这两种情形。

Laya 为此搭了一个独立的行动判断网络。输入是一千零二十八维的向量。前一千零二十四维来自整篇文章经池化后的全局语义表征。后四维反映概率分布的形状，分别是最高概率、前两名概率的差值、归一化香农熵、选项数量与上限的比例。

语义向量让网络感知输入本身的复杂度。四维统计量让它读懂概率分布的形状，能区分势均力敌和一骑绝尘。两部分拼在一起送入一个两层小网络，输出两个动作的概率，允许自动执行还是升级给人工。

前面提到的闭集异常输入，正是在这一步被兜住。哪怕前端局部打分给出了虚高的离散分布，异常输入的全局语义表征依然会脱离正常分布，加上归一化香农熵对不确定性的捕捉，行动网络能直接察觉异样，阻断盲目执行。

行动的门槛直接从成本账里算出来。假设自动执行且正确，收益记为正一分。自动执行却做错了，惩罚负三分。拿不准转人工，固定成本负零点五分。

设模型的把握为 p，自动执行的期望收益是 p 乘正一加上 (1-p) 乘负三，化简后是 4p 减 3。转人工的开销固定负零点五。让 4p 减 3 大于负零点五，解出 p 大于 0.625。

模型在训练时被这套损益矩阵考核，网络内部自然会学出一条底线。置信度不到六成出头时，自动执行在统计上就是亏本买卖，系统老老实实交出控制权。

这套门控逻辑能够运转，前提是概率数字本身值得信赖。独立研究者 Archer Hume 曾对 Jev 商业接口做过一次系统性的测谎实验，用一千两百道标准化测试题评估模型的校准表现，测得的期望校准误差只有零点零三一。还有一组更直观的数据，在三十道简单乘法题上，模型答对了百分之八十六点七，它自己报出的平均把握是百分之八十三，两者高度吻合。当题目换成难度更大的两步应用题，正确率骤降至百分之三十二，模型同时把自报把握主动降到了百分之三十。这种置信度随难度同步下降的特征，直接来自 RLCD 训练目标的校准。

## 六、打包多维度问题的系统级并发

在真实业务中，很少有一封邮件或一条工单只需要做单一维度的判断。通常一封客户邮件进来，系统同时需要回答好几个问题。比如分流到哪个部门，紧急程度是几级，客户有没有流失倾向，内容里是不是夹带了恶意钓鱼或越狱代码。

如果依赖通用大模型，要么排队串行调用四次，累计耗时数秒；要么把四个问题硬塞进一段很长的 Prompt 里，指望大模型一次性吐出复合 JSON，极易出现漏字段或格式损坏。

动态分类模型只有几亿参数，显存占几百兆。工程上完全可以把同一份邮件正文，跟这四个问题的描述一起打成单个批次送进显卡。GPU 只要跑一次前向传播，三十来毫秒就能把全部维度的判定结果同时拿回来。这种高并发批处理能力，才让它能在密集状态机里充当低延迟判定节点。

多个问题并发时，工程上有现成的办法保证它们互不串台。在像 ModernBERT 这样的双向编码器里，拼接输入序列时只要给各问题区域加上动态注意力掩码，把非本题区域的权重强制置零，每道题就只能看见共享的正文和它自己的选项。若是在使用因果解码器复现的项目里，则可以在编码完正文后把中间状态冻结住，再以此为起点分出几条平行的前向分支。Archer Hume 曾用一个暗号实验验证过这种物理隔离。他在问题 A 的描述中嵌入一段暗号，然后让问题 B 去猜这个暗号，Jev 给出正确答案的概率严格为零。但如果把同一段暗号移到所有问题共享的状态文本里，问题 B 的正确率瞬间跳到百分之九十以上。共享的上下文所有问题都看得见，相邻问题之间则绝对无法偷看。

## 七、拼成代码

把上面的设计组装成一个 PyTorch 模块。

```python
import math
import torch
import torch.nn as nn
import torch.nn.functional as F


class DynamicClassificationHead(nn.Module):
    def __init__(self, hidden_dim=1024, num_decision_layers=2):
        super().__init__()
        self.hidden_dim = hidden_dim

        # 顶层决策层，让各选项的掩码向量互相计算注意力
        encoder_layer = nn.TransformerEncoderLayer(
            d_model=hidden_dim,
            nhead=8,
            dim_feedforward=hidden_dim * 2,
            activation="gelu",
            batch_first=True,
        )
        self.decision_layers = nn.TransformerEncoder(
            encoder_layer,
            num_layers=num_decision_layers,
        )

        # 选项评分器，把每个掩码向量映射为一个标量分值
        self.option_scorer = nn.Sequential(
            nn.Linear(hidden_dim, hidden_dim // 2),
            nn.GELU(),
            nn.Linear(hidden_dim // 2, 1),
        )

        # 行动判断头，接收全局语义与四维分布统计量
        self.act_head = nn.Sequential(
            nn.Linear(hidden_dim + 4, 128),
            nn.GELU(),
            nn.Linear(128, 2),
        )

    def forward(self, hidden_states, mask_indices, cls_vector=None, temperature=1.0):
        batch_size, seq_len, dim = hidden_states.shape
        num_options = mask_indices.shape[1]

        # 经过顶层决策层增强选项间的排他竞争
        enhanced = self.decision_layers(hidden_states)

        # 用 gather 抽取各选项 [MASK] 位置的隐藏向量
        idx = mask_indices.unsqueeze(-1).expand(-1, -1, dim)
        option_reps = torch.gather(enhanced, dim=1, index=idx)

        # 映射为标量分值并按温度缩放
        logits = self.option_scorer(option_reps).squeeze(-1)
        probs = F.softmax(logits / temperature, dim=-1)

        # 提取四维分布统计量
        max_p, _ = torch.max(probs, dim=-1, keepdim=True)
        top2, _ = torch.topk(probs, k=min(2, num_options), dim=-1)
        if num_options >= 2:
            margin = (top2[:, 0] - top2[:, 1]).unsqueeze(-1)
        else:
            margin = torch.ones_like(max_p)

        eps = 1e-9
        entropy = -torch.sum(probs * torch.log(probs + eps), dim=-1, keepdim=True)
        norm_entropy = entropy / math.log(max(num_options, 2))
        budget_ratio = torch.full_like(max_p, num_options / 255.0)

        stats = torch.cat([max_p, margin, norm_entropy, budget_ratio], dim=-1)

        # 拼接语义向量与统计量，判断是否放行
        if cls_vector is None:
            cls_vector = enhanced[:, 0, :]
        action_logits = self.act_head(torch.cat([cls_vector, stats], dim=-1))

        return probs, action_logits
```

## 八、让小模型当网关，大模型做生成

这种轻量分类头不是为了去争大模型的位置，它做的是把两者在系统里的分工拆开。

几亿参数的前向模型适合放在最前面当流量网关，专接高频琐事。工单分流、工具参数合规检查、意图识别以及安全拦截，三十毫秒就能过一遍，把八成以上的常规判定挡在前面。包括模型路由本身也是一次分类，原本就没必要请昂贵的推理模型来判断该不该调用推理模型。

百亿或千亿参数的大模型则退到后面，只在真正需要写长文本、解释复杂逻辑或做多跳推理时再接手。

不过真把这套东西接进流水线，也得先算清一笔账。分类模型自己跑得快，但如果盲目接进流水线，反而可能因为误判导致重试，拉长整个智能体的耗时。它最管用的地方，是那些标准明确、证据集中、判断错了能兜底或容易复核的环节。如果后续的大模型本来就能顺手筛出关键信息，盲目在前面加一层拦截器，一旦误判引发来回重试，整条链路的端到端延迟反倒会翻倍。

模型读完文本之后，分类头只做两件事。一件是把运行时出现的选项抽出来打分，另一件是看看分数的分布形状，判断这次该不该自己拿主意。能用几个浮点数解决的选择题，确实不必让自回归解码器跑一圈。
