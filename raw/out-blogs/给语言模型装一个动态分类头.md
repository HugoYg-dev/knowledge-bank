# 给语言模型装一个动态分类头

做智能体的时候，到处都要做选择。挑工具、给工单分流、判断一段内容是否合规，这些事过去一律交给通用大模型，构造一段提示词，让几十亿参数的自回归模型逐字吐出一段 JSON。慢的时候两秒，快的时候也要几百毫秒，偶尔还会编造工具名，或者 JSON 截断在半路上。

很多人尝试给大模型套上 JSON 约束或结构化输出。这确实管住了格式，输出不会再缺括号，但没解决速度问题。底层依然在自回归循环里转圈，GPU 照样要机械地逐字吐出大括号、字段名、冒号和引号。如果业务要的是高频判定，带着语法约束生成终归也是生成，自回归解码带来的显存带宽开销一点没少，几十毫秒的硬指标依然过不去。

2026 年 9 月 Jev 走红。这个模型完全不生成文字，给它一段状态描述和预设选项，只返回各选项的概率和置信度，延迟七八十毫秒，官方公布的输入单价是每百万 token 0.042 美元，约为前沿大模型的四百分之一。

开源社区的反应很快，上线不到三天，就有人用几行代码在 Qwen 4B 上跑通了单步打分的推理路径。结合本地读 logits 的 SemIf、塞进浏览器的 jev-fire、Convai 开源 4.21 亿参数的 Laya，以及 Archer Hume 的黑盒测谎实验来看，**让语言模型直接跳过文本生成、单步输出校准概率的技术路线已经非常清晰。**

## 一、直接从因果语言模型里抽取分值

现代因果语言模型的输出层本身就是一个大型线性分类器。如果模型的隐藏维度是 1000、词表大小 150,000，最后一层的权重就是 $1000 \times 150000$ 的矩阵。平时生成文本，模型是在这 15 万个候选词里逐个算概率挑下一个词；如果任务只是判断一封工单该转给财务、技术还是销售，候选缩到了 3 个，两边差了五万倍。

**最快的复现方式不需要训练任何新权重。** 提示词送进去跑一次前向传播，取出序列末尾的隐藏状态送入输出层，拿到 150,000 维的分值向量后，直接丢掉其余 149,997 个无关词，只抽出那 3 个候选词对应的分值，在这个小集合内部重新做 Softmax。从概率论看，这一步算的是条件概率，在已知输出必然落在这三个词的前提下，各选项分别占多少。

据社区公开对比评测，开源项目 SemIf 用完全冻结的 Qwen 4B 跑这套逻辑，零训练零微调，在 Jev 官方 102 个判断任务上达到了 84.5% 的准确率，对比 Jev 自己的 88.3%，差距不到四个百分点。另一个叫 jev-fire 的项目则把 0.8B 参数的 Qwen 模型塞进浏览器用 WebGPU 运行，单步决策 71 毫秒，比 Jev 云端 API 的 178 毫秒中位延迟还快，API 费用也直接省掉了。

工程落地上，这套逻辑也不需要自己手动侵入 PyTorch 源码去截取张量。像 SGLang 这样的现代推理引擎已经把 `/v1/score` 打分端点收录为原生接口，客户端传过去提示词和候选词对应的标记编号，服务端在前向传播结束的瞬间直接在显存内完成切片和局部归一化。

```python
import requests

# 工业推理引擎将此抽象为单次打分请求，无需进入解码循环
response = requests.post("http://localhost:30000/v1/score", json={
    "query": prompt,
    "label_token_ids": [token_A, token_B, token_C],
    "apply_softmax": True
})
probabilities = response.json()["scores"]
```

拿到的直接是离散概率分布，整个过程完全跳过了生成循环。几行代码就能跑通这件事，说明从前向传播中提取指定标记的分值并做局部归一化，在算法层面已经相当透明。

## 二、分词器里的陷阱与闭集防线

跑通单步打分之后，工程落地最容易踩坑的地方出在分词器上。现代语言模型普遍采用字节对编码（BPE，Byte Pair Encoding）分词，**同一个单词前面带不带空格，编码出来的标记编号完全不同**。比如 `billing` 单独出现时编号可能是一万四，前面加个空格就变成两万八。提示词里候选标签紧跟上文，自然带着前缀空格；代码在查找词表索引时一旦漏掉这个空格，拿到的就是另一个语境下的分值，概率分布会严重跑偏。

更棘手的问题出在长单词上。有些词没办法用单个词元覆盖，比如 `technical` 会被分词器切成 `tech` 和 `nical` 两段。取第一段 `tech`，它的分值实际覆盖了所有以 `tech` 开头的单词（`technology`、`technician`、`tech lead`），概率虚高；取最后一段 `nical`，由于前文没有出现 `tech` 前缀，模型在当前位置预测一个孤立 `nical` 的概率接近零，这个选项会被直接误杀。而且长词拆成多个词元后，多步条件概率连乘还会引入长度惩罚偏差。

社区在工程上有两套应对办法。最稳妥也最省事的做法，是在提示词里把选项编成代号，写清楚 A 代表财务、B 代表技术、C 代表销售。在绝大多数主流分词器里，单字母只占一个词元，不会被切碎；模型读完上下文和选项说明后，注意力机制已在末尾吸收了完整语义，单选一个字母几乎没有分词损耗。如果业务非要直接对长短不一的自然语言短语打分，就不能只看末尾单个词元，只能沿着词组逐字算条件概率，把各步对数似然累加起来，再除以带惩罚因子的长度系数 $|W|^\alpha$，抵消长词概率天然偏低的衰减。

**绕过分词陷阱后，还要防备闭集计算带来的数学假象。** 局部 Softmax 算的是条件概率，建立在「真实答案必然落在给定候选项内」这个强假设上。一旦系统遭遇黑客注入邮件或完全无关的异常输入，由于分母被锁死在三个选项之间，错误选项依然会被强行分走全部概率，甚至可能由其中某项高分胜出。

闭集打分必须留一条退路。最直接的做法是在候选项里永远保留一个退路标记，比如 D 对应「其他」或「转人工」，给范围之外的输入留出安全出口；更底层的防线，则要靠模型在全局表征层面识别出输入已经脱离预设范围。

## 三、因果解码器做分类的天花板

即便应付了分词与闭集问题，因果解码器自身的结构限制依然绕不过去。

因果掩码规定信息只能单向流动，前面的字看不见后面给出了哪些选项，上下文与候选描述之间的语义交互从一开始就不对称、不完整。硬件效率上同样不经济，自回归生成是典型的显存带宽受限任务，每吐一个字都要把几十亿参数重读一遍；单步打分虽然用密集矩阵乘法跑满了算力，但为了比对 3 个选项的相对高低，GPU 依然要先算出 150,000 维的词表分值再扔掉绝大部分，同时还要为自回归架构维护键值缓存（KV Cache，Key-Value Cache）的显存与调度开销。

如果业务需要的是高频调用、每次只要几个浮点数的判断节点，值得换成专门的双向编码器架构。

## 四、双向编码器加动态掩码

Convai 开源的 Laya 模型在这件事上给出了一套完整方案。它选用 3.95 亿参数的 ModernBERT-large 做主干（算上顶层决策头与行动网络，全模型总计约 4.21 亿参数），包含 28 层 Transformer、隐藏维度 1024，采用全双向注意力。

全双向意味着输入序列里的每一个字、每一个选项描述，在每一层都能互相看见。状态文本和候选选项之间的语义匹配是完全对称的，硬件上整个推理变成一次密集矩阵乘法，能把 GPU 的 Tensor Core 打满，实测耗时 33 到 38 毫秒。光换主干还不够，过去 BERT 做分类是在句首标记后接固定大小的全连接层，类别数写死在代码里；**实际业务中选项随时在变，分类头必须支持运行时动态绑定。**

### 把选项写进输入序列

Laya 的做法是在组装提示词时，给每个选项描述末尾插入一个 `[MASK]` 标记。比如一封退款邮件需要判断转给哪个部门，拼出来的输入就是邮件正文在前，后面依次排列各候选部门的描述，每段描述末尾跟一个 `[MASK]`。这些 `[MASK]` 在全双向注意力下同时聚合邮件正文和各自部门说明，并在同一层里兼顾其他选项。不管传入 2 个选项还是 20 个，只要在输入里增减 `[MASK]` 数量，网络结构一点不用改。

### 顶层决策变换层

主干编码完成后，Laya 额外叠加了两层 Transformer 决策层，再送去抽取各选项向量。整条序列经过这两层交互后，各个 `[MASK]` 位置既能继续参考共享的上下文语义，又能让不同选项向量之间互相计算注意力，拉开彼此的区分度并建立竞争关系。

### 用 `gather` 算子精准抽取

文本长短不一，每个 `[MASK]` 在序列中的物理位置动态变化，短邮件的 `[MASK]` 可能在第 15 位，长邮件可能跑到第 300 位。程序在分词阶段记下每个 `[MASK]` 的索引位置，随后调用 PyTorch 的 `gather` 算子，直接按索引从几百行的大矩阵里抽出目标行，拼成规整的候选张量。这步只做显存地址重排，耗时在微秒量级。

### 动态缩放校准与三种原语统一

抽出来的向量经全连接网络映射为标量分值后，不能直接用固定温度做 Softmax。选项数量一变，分母上的累加项就变了，2 个选项时瞎蒙的概率是 50%，20 个选项时只有 5%；同样输出 70% 的概率，前者没多大把握，后者说明模型非常确定。为了让输出概率保持一致的统计意义，Laya 针对任务类型和选项数量预先拟合了缩放参数，在 Softmax 前对分值做调节。

把打分标尺统一之后，智能体里五花八门的选择题基本都能收敛到三种形态。无序单选（如工单路由、意图识别）直接吐出各选项的离散概率与置信度；有序评级（如故障严重度 0 到 3 级）除给出各档位概率外，还能用期望公式 $\mathbb{E}[S] = \sum i \cdot p_i$ 算出连续平滑的分值（比如 1.84 级），保留程度上的渐变；是非题（如钓鱼拦截、越狱检测）则直接输出经过校准的风险概率。

### 用校准决策强化学习让概率不撒谎

温度缩放解决了选项数量变化带来的分母漂移，可下游程序凭什么把模型吐出的概率数字当真？传统交叉熵分类只有当正确选项分值趋近无穷大时损失才最小，模型天然被推向过度自信；标准强化学习采用命中得 1 分、落空得 0 分的二元奖励，同样会把最高概率往 1.0 硬拉，压扁其余选项并破坏校准度。

**Jev 和 Laya 走的路线是校准决策强化学习（RLCD，Reinforcement Learning for Calibrated Decisions），核心是把奖励函数换成严格适当评分规则。** 在决策理论里，一个评分规则被称为严格适当，当且仅当报告的概率分布恰好等于真实分布时，期望得分才唯一达到最大值。只有如实报告把握，模型才能拿到最高奖励，任何虚报都会扣分。Laya 在训练中组合了三种评分，对数评分重罚对正确类别给低概率的情况，球面评分提供有界平滑信号以防梯度爆炸，排序概率评分则专门教模型理解有序量表各档位之间的远近。

事后温度缩放只是拿固定系数在推理期拉平整体分布，无法针对具体样本区分把握高低；RLCD 则在训练阶段直接把校准写成优化目标，改变模型权重本身。

## 五、系统该不该自己拿主意

拿到分类概率之后，单靠最高概率设阈值很容易在业务里翻车。比如面对两个选项给出 51% 和 49% 的概率，最高分勉强过半，但两个选项咬得死紧，误判风险极高；而十个选项里第一名拿到 60%、其余九个都在 4% 上下时，虽然绝对值只有六成，它却高出第二名五十多个百分点，模型其实非常笃定。

为了区分这两种局面，Laya 搭了一个独立的行动判断网络。输入是 1028 维向量，前 1024 维来自整篇上下文经池化后的 `[CLS]` 全局语义表征，后 4 维反映概率分布形状，分别是最高概率、前两名概率差值、归一化香农熵，以及选项数量与系统上限 255 的比例（$K / 255$）。语义向量负责感知输入本身是否复杂或异常，四维统计量负责读懂分布形状；两部分拼在一起送进两层网络，输出「自动执行」和「升级给人工」两个动作的概率。前面提到的闭集异常输入，也正是在这一步被全局语义表征和归一化熵兜住，阻止盲目执行。

行动的门槛直接由 Laya 的成本敏感奖励矩阵算出。**在训练规则里，自动执行且结果正确记 +1.0 分，自动执行却做错惩罚 -3.0 分，拿不准升级给人工的固定成本是 -0.5 分。** 设模型的把握为 $p$，自动执行的期望收益是 $p \cdot 1 + (1 - p) \cdot (-3)$，化简后是 $4p - 3$；只有当 $4p - 3 > -0.5$、即解出 $p > 0.625$（62.5%）时，自动执行才划算。受这套损益矩阵考核，模型内部会自然学出一条底线，置信度不到六成出头时老老实实交出控制权。

这套门控能够成立，前提是概率本身值得信赖。独立研究者 Archer Hume 曾对 Jev 商业接口做过系统性的测谎实验，在 1200 道标准化测试题上测得的期望校准误差只有 0.031。在 30 道简单乘法题上，Jev 答对了 86.7%，自报平均把握是 83%，两者高度贴近；当题目换成难度更高的两步应用题，正确率跌到 32%，模型也同时把自报把握降到了 30%。置信度随题目难度同步下调，正是校准训练带来的特征。

## 六、打包多维度问题的系统级并发

在真实业务里，一封客户邮件进来往往需要同时回答好几个问题，比如分流到哪个部门、紧急程度几级、有没有流失倾向、里面是否夹带钓鱼或越狱内容。如果依靠通用大模型，要么串行调四次累计耗时数秒，要么把四个问题硬塞进一段很长的提示词里指望一次性吐出复合 JSON，极易漏字段或破坏格式。

动态分类模型只有几亿参数，显存占用不过几百兆。工程上可以把同一份邮件正文跟这几个问题拼成批处理输入，一次送进显卡前向传播，三十多毫秒就能把全部维度的判定结果拿回来。

多个问题并发时，工程上也有现成办法保证它们互不串台。像 ModernBERT 这样的双向编码器，可以在拼接序列时为每个问题区域加上动态注意力掩码，把非本题区域的注意力权重强制置零，使每道题只能看见共享正文和它自己的选项；而采用因果解码器的复现项目，则可以在编码完共享正文后冻结键值缓存，再以此为起点分出多条平行前向分支。Archer Hume 曾做过一个暗号实验验证 Jev 的物理隔离，他在问题 A 的描述里塞入暗号「ZEBRA-7741」，然后让问题 B 去猜这个暗号，Jev 选中正确答案的概率严格为 0；可只要把同一句暗号挪到所有问题共享的状态文本里，问题 B 的正确率立刻跳到 90% 以上。共享上下文对所有题目开放，相邻题目之间则严格隔离。

## 七、拼成代码

把上面的动态分类头与行动判断网络组装成一个 PyTorch 模块。需要注意，如果调用方没有单独传入全局池化向量 `cls_vector`，下面代码默认回退取 `enhanced[:, 0, :]`（对应 `[CLS]` 位置的表示）。

```python
import math
import torch
import torch.nn as nn
import torch.nn.functional as F


class DynamicClassificationHead(nn.Module):
    def __init__(self, hidden_dim=1024, num_decision_layers=2, max_options=255):
        super().__init__()
        if max_options <= 0:
            raise ValueError("max_options 必须大于 0")
        self.hidden_dim = hidden_dim
        self.max_options = max_options

        # 顶层决策层，在全序列上进一步交互并强化各选项的区分度
        encoder_layer = nn.TransformerEncoderLayer(
            d_model=hidden_dim,
            nhead=8,
            dim_feedforward=hidden_dim * 2,
            activation="gelu",
            batch_first=True,
        )
        self.decision_layers = nn.TransformerEncoder(
            encoder_layer,
            num_layers=num_decision_layers,
        )

        # 选项评分器，把每个掩码向量映射为一个标量分值
        self.option_scorer = nn.Sequential(
            nn.Linear(hidden_dim, hidden_dim // 2),
            nn.GELU(),
            nn.Linear(hidden_dim // 2, 1),
        )

        # 行动判断头，接收全局语义与四维分布统计量
        self.act_head = nn.Sequential(
            nn.Linear(hidden_dim + 4, 128),
            nn.GELU(),
            nn.Linear(128, 2),
        )

    def forward(
        self,
        hidden_states,
        mask_indices,
        cls_vector=None,
        key_padding_mask=None,
        temperature=1.0,
    ):
        if temperature <= 0:
            raise ValueError("temperature 必须大于 0")
        batch_size, seq_len, dim = hidden_states.shape
        num_options = mask_indices.shape[1]
        if num_options == 0:
            raise ValueError("mask_indices 至少需要包含一个选项")

        # 经过顶层决策层交互后再抽取选项表征（变长批处理传入 key_padding_mask 防串台）
        enhanced = self.decision_layers(
            hidden_states,
            src_key_padding_mask=key_padding_mask,
        )

        # 用 gather 抽取各选项 [MASK] 位置的隐藏向量
        idx = mask_indices.long().unsqueeze(-1).expand(-1, -1, dim)
        option_reps = torch.gather(enhanced, dim=1, index=idx)

        # 映射为标量分值并按温度缩放
        logits = self.option_scorer(option_reps).squeeze(-1)
        probs = F.softmax(logits / temperature, dim=-1)

        # 提取四维分布统计量
        max_p, _ = torch.max(probs, dim=-1, keepdim=True)
        top2, _ = torch.topk(probs, k=min(2, num_options), dim=-1)
        if num_options >= 2:
            margin = (top2[:, 0] - top2[:, 1]).unsqueeze(-1)
        else:
            margin = torch.ones_like(max_p)

        eps = 1e-9
        entropy = -torch.sum(probs * torch.log(probs + eps), dim=-1, keepdim=True)
        norm_entropy = entropy / math.log(max(num_options, 2))
        budget_ratio = torch.full_like(max_p, num_options / float(self.max_options))

        stats = torch.cat([max_p, margin, norm_entropy, budget_ratio], dim=-1)

        # 拼接语义向量与统计量，判断是否放行
        if cls_vector is None:
            cls_vector = enhanced[:, 0, :]
        action_logits = self.act_head(torch.cat([cls_vector, stats], dim=-1))

        return probs, action_logits
```

## 八、让小模型当网关，大模型做生成

**轻量分类头与通用大模型在系统里各管一摊。** 几亿参数的前向模型放在最前面当流量网关，专接高频琐事，工单分流、工具参数合规检查、意图识别和安全拦截三十毫秒就能过一遍，把八成以上的常规判定挡在前面；包括模型路由本身也是一次分类，没必要请昂贵的推理模型来决定该不该调用推理模型。百亿或千亿参数的大模型退到后面，只在需要写长文本、解释复杂逻辑或做多跳推理时接手。

真把这套组件接进生产流水线，还得先算清经济账。它最管用的位置是标准明确、证据集中、判错了容易复核或重跑的节点；如果后续的大模型本来就必须跑一遍且能顺手做完筛选，强行在前面加一层拦截器，一旦误判引发来回重试，整条调用链的端到端延迟反而会翻倍。
