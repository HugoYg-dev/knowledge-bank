# 读论文 JitRL，免梯度更新的 LLM Agent 测试时强化学习

这篇笔记读的是新加坡国立大学团队发表在 ICML 2026（Spotlight）的论文 [Just-In-Time Reinforcement Learning (JitRL)](https://arxiv.org/abs/2601.18510)。顺着最近一直在看的「经验库驱动智能体自进化」这条线往下读，JitRL 给出的解法很干脆，**全程冻结模型权重，在测试时检索经验记忆来估计动作优势值，然后直接修改模型输出的 logits，不触发任何梯度更新。**

## 为什么不在部署后继续训权重

LLM Agent 部署到生产环境之后，模型权重通常就冻结了，面对新环境很难继续适应。如果走传统强化学习微调，算力开销高，还容易在适配新任务时引发灾难性遗忘。

另一条路是把过往经验写进提示词里做上下文学习，但提示词有长度上限，更重要的是，很多操作技能很难凝练成几句顺畅的文字规则。JitRL 想解决的正是这个夹缝，既不动权重，也不全靠提示词硬塞。

## 靠经验检索和评估器跑通测试时更新

JitRL 把测试时策略优化拆成了推理与回写两步。推理阶段，系统按当前状态去记忆库里检索相似的历史轨迹，算出各候选动作的优势值，直接加到模型输出的 logits 上再选动作。

每轮任务结束后，系统会交由评估器模型对整条轨迹做步级奖励归因，再把后续奖励按折扣率累加为每一步的回报。最后把「状态、动作、回报」三元组存回记忆库，供后续任务检索。

## 怎么算优势值，又如何控制探索

具体的非参数估计算法围绕记忆库里的近邻样本展开。状态价值由所有相似邻居轨迹的回报取平均得到，动作价值则只取同动作邻居回报的平均，两者相减就是该动作的优势值。

如果某个候选动作在记忆库里还没出现过，JitRL 会遵循「不确定就保持乐观」的原则给它加上探索加成。随着相似经验越攒越多，这个探索加成会自动减小，策略也就自然从探索过渡到利用。

## 为什么加法改 logits 在理论上站得住

很多测试时启发式做法靠经验拍脑袋调参数，**JitRL 在理论上证明了「原 logits 加上 $\beta$ 倍优势值」这条加法规则，正是 KL 散度约束下策略优化目标的精确闭式解。** 换句话说，随着经验记忆不断积累，非参数检索估出的价值会逼近真实价值，调制后的整体策略也会逼近 KL 正则下的最优策略。

落地到具体模型接口时，只要模型开放了词表对数概率（logprob）接口，就可以直接取候选动作对应序号 token 的对数概率当作 logits 来加减；如果是完全不返回 logprob 的黑盒商业 API（比如 Gemini、GPT 或 DeepSeek 的部分接口），也可以让模型先自报各选项置信度，再换算成口头化对数几率（verbalized logit）来参与调制。

## 论文实验效果与开销对照

据论文在网页操作与文字游戏基准上的实测数据，JitRL 在 WebArena 上的最终成功率为 51.35%，高于最强免训练基线的 43.00%；在留出测试集上拿到 60.00%，超过了需要参数微调的方案 WebRL（46.06%）。在 Jericho 文字游戏基准的 Zork1 关卡中，JitRL 取得平均 53.0 分，而采用梯度强化学习训练的 GRPO（Group Relative Policy Optimization，组相对策略优化）只有 16.2 分。

成本差距同样悬殊。按论文对实验开销的统计与估算，WebRL 训练动用 H200 集群跑了约 154 小时，算力成本估算约 9,900 美元；**JitRL 全程只走 API 调用，总开销约 290 美元**，与其他免训练方法处于同一量级，比 WebRL 便宜了超过 30 倍。

## 在经验驱动进化谱系里的位置

把 JitRL 放进「用经验库驱动智能体持续改进」的几项代表性工作里对照，它的取舍就更清楚了。

同样靠经验积累提升表现，EvolveR 选择把历史轨迹蒸馏成不断压缩整理的文字原则库，再用 GRPO 把检索方法和原则用法训进模型参数里；JitRL 则反其道而行，不做文字抽象，只攒最原始的「状态、动作、回报」三元组，也不做梯度更新，直接拿记忆库当非参数价值函数。

方法上跟 JitRL 最接近的免梯度工作是 ProcMEM。两者都采用非参数优势估计，不过 ProcMEM 会进一步把经验固化成可调用的技能模块，而 JitRL 保留原始经验条目，省去了这层技能抽象。另一个思路呼应的工作是 GAM，它同样冻结主模型权重、把计算推到测试时，只是 **GAM 管的是输入侧往上下文里放什么，JitRL 管的是输出侧怎样直接调制动作概率。**
